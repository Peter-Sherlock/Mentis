# ADR-006：首产品试点与领域组合

| 字段 | 内容 |
| --- | --- |
| 状态 | proposed（本轮架构建议；用户尚未明确确认具体领域） |
| 日期 | 2026-09-27 |
| 来源包 | P0.3 |
| 来源 | 用户要求修改规划，并研究初始领域及不同领域的切换方式 |

## 建议

首产品试点选择小型网页的界面与交互设计；Mentis 负责目标形成、委托、作品诊断及修改指导，执行型 Agent 负责实现。原文档问答方向保留为工程回归草案。

共用协作内核，按任务/产物/决策加载少量专业资源，并核对独立的执行与观察能力。不能每个职业各写一套完整工作流，也不能宣称仅靠自动检索就能胜任任何领域。

## 取舍

网页允许在本地反复检查渲染、结构和交互，适合验证含糊反馈与修改效果；审美分歧要求用户参与与独立评价。视频更直接涉及导演知识，但成片需要时间维度观察与生成工具；装修还涉及真实空间与可实施条件。详细比较见 [领域策略](../DOMAIN_STRATEGY.md)。

## 影响

P0.4 按该暂定范围设计可逆的案例与评价方案，持续保留 proposed 标签。后续用户明确选择时更新此状态及依赖，不把本轮“请修改”扩写为“用户已确认网页领域”。

新领域迁移是后续单独实验；首版只验证已声明任务范围及未知领域受限处理。更換 Coding Agent 不等于领域切换。

## 重评条件

用户偏向另一个领域；观察工具不可用；试点难以产生有区分度的反馈；评审资源不足或强基线已充分解决任务。按证据收窄或更换试点，不自动扩大系统。
