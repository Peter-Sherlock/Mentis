# ADR-003：完整 MVP 的完成定义

| 字段 | 内容 |

| 状态 | selected（原完整 MVP 边界保留；开发顺序按 v0.2 修订） |
| 更新 | 2026-09-27，P0.3 |

## 保留的完成定义

完整 MVP 仍同时需要功能、证据与交付材料：
- 两个真实执行器，统一任务语义和实际审核、修订记录。
- 必要状态/权限/版本测试，公平强基线、独立评价、正式保留集和目标用户试用。
- 安装、配置、能力范围、成本、恢复与限制说明。
- 价值未证实时准确交付为“工程可运行，价值尚未证实”，不能仅凭功能完成宣布 MVP 通过。

原 6—10 人的形成性招募目标保留为规划规模，不能解释为统计充分性保证。无人参加时真实用户证据未完成。

## 顺序修订

单执行器最小真实闭环前移，并尽早开展 P5.2a；该阶段称研究原型。随后做 P2.4 价值比较，再完善持久化、恢复、界面，最后第二执行器与正式评测。首次验证价值不需要等待完整 MVP。

新领域迁移实验不自动纳入本次完整 MVP；两执行器通过不能称为跨领域通过。

## 影响

PROJECT_PLAN、DEVELOPMENT_PLAN、状态文件采用同一顺序。旧 8—12 周估算失去当前承诺意义，在实际闭环之后重估。原选择和历史工期见 [原记录](../archive/pre-v0.2/docs/decisions/ADR-003.md)。

## 重评

核心收益未建立、第二执行器长期不可用或用户改变边界时，保留原证据，明确限制或修订范围。
