## 已由用户决定的输入方向

以下方向为用户在 2026-09-27 产品讨论中明确表达（记录于 [PROJECT_PLAN §2.1](../PROJECT_PLAN.md)），本目录各 ADR 以其为约束，不重新询问：

- U-01 先讨论产品、架构和 MVP，再实现。
- U-02 Agent 代表用户进入不熟悉的专业领域；核心不能退化为提示词润色工具。
- U-03 重视 Knowledge Gap Detection 与专业需求挖掘；必须有显式缺口模型与评测。
- U-04 形成 Professional Specification；要求、假设、来源、验收可追踪。
- U-05 需要 定义—委托—审核—修订 闭环；执行器最终回答不直接当成交付。
- U-06 专业性体现在架构中；领域规则、工具、验证和能力边界参与控制流程。
- U-07 处理 Fake Expertise；区分事实陈述、推断、建议和未验证结论。
- U-08 保留人的参与及创造性贡献；人能探索、质疑、修改目标和决定取舍。
- U-09 不绑定 Codex，支持其他 Coding Agent；执行契约与接入协议分离。
- U-10 追求技术深度，逐步完成；以真实任务和对照评测决定扩展。

## 维护规则

- 每项决定状态只能由真实依据改变：用户确认、用户指定方案或授权范围内按计划落实。
- pending 项不得在后续工作包中当作已定内容使用；确需使用时先取得用户确认。
- 修改已 selected 的决定需更新记录、注明新来源与重评理由，并检查受影响工作包。
- 具体数值类门槛（ADR-005）在首次运行对应保留集评测前冻结，冻结后不得因结果修改。
