# Mentis 下一版本开发大纲：本地浏览器闭环与任务专业配置

版本：v1.0｜2026-10-08｜性质：负责人授权更新的开发大纲，具体进度仅见[状态文件](DEVELOPMENT_STATUS.md)。技术包依赖见[开发计划](DEVELOPMENT_PLAN.md)，下一轮指令见 [P2.4-O2](prompts/P2.4-O2.md)。

## 1. 版本目标与优先级

下一版先面向本机单用户、现有小型网页任务：启动服务 → 浏览器给目标 → Mentis 自主制作与检查 → 必要节点介入 → 查看作品 → 表达反馈并核对修订。当前本地只读页继续复用，最终交互入口无需域名或公共部署。

优先顺序：可靠运行状态与最小专业配置 → 可使用的本地浏览器闭环 → 不同网页任务的效果验证 → 受控自动优化。最小配置是本版底座；自动优化单列后续研究，不在当前包实现。Mentis 负责需求、方案、专业判断与指导，执行器负责具体制作；职业称谓不作为能力证明。

本地服务负责界面、编排与文件；当前模型/执行器仍需相应账号、连接与运行条件。安装、启动和费用/用量提示须按实际接入写明，不能让用户误以为模型完全离线。

## 2. 开发顺序与退出门槛

| 步骤 | 所属范围 | 主要交付 | 退出门槛 |
| --- | --- | --- | --- |
| 1 | P2.4-O2 | 阶段、等待、耗时、生产者活动和最后可靠状态；CLI/现有页面共用 | 长等待/超时/异常/待决/终态/恢复能准确解释；历史缺采集明确显示；旁观器不改变任务 |
| 2 | P2.4-C1 | 本次任务的专业配置、资源快照与阶段绑定；页面按需查看 | 配置先落盘；同任务阶段使用同一有效版本；更新有原因、旧版本不改写；保持盲评隔离 |
| 3 | P2.4-O3 完整核验 | 至多一次登记预算的真实网页任务与三个作品入口 | 含真实委托、观察、判断和版本证据；O2/C1 真实链路表现单列；失败留档，历史 E2 不改 |
| 4 | P1.3 → P1.4 → P3.3 | 持久化、故障回归及真实恢复/中断 | 页面连接不控制任务生命周期；重复事件不重复派发；unknown 保持核对语义；恢复不复活撤回授权 |
| 5 | P3.4 | 本地浏览器任务发起、交流、反馈、预览和比较 | 完成一次真实任务与反馈；刷新/重连不重复提交，异常可查已保存作品；暂停请求与确认停止分列 |
| 6 | P2.4 方法验证/后续评测 | 多种网页任务的配置适配、强基线比较和独立评价 | 质量、回归、成本、用户负担分别报告；身份一致性与效果分别结论 |
| 7 | 后续受控优化研究 | 候选配置、比较报告、版本晋升和回退办法 | 评价与数据隔离先具备；未达到门槛不自动发布 |

以上是体验目标下的技术分解，保留 22 个顶层工作包及包间依赖。C1 是 P2.4 内部补强，不新增整套 Agent。P2.4 价值结论可能为负面或不确定，必须记录继续/简化/收窄依据；只读页面或配置通过不能替代独立评分。已有适用授权继续复用，不增加每轮用户审批。

## 3. 最小任务专业配置（P2.4-C1）

### 职责与数据

复用 CapabilityContext、brief、DelegationPolicy、EvaluationPlan 和 O1 调用记录，避免另建平行事实来源。

| 内容 | 最小记录 |
| --- | --- |
| 专业职责 | 网页任务的需求、方案、指导、观察与验收责任；明确不支持范围 |
| 专业依据 | 资源 id、版本、内容 SHA-256、适用理由、来源及复核状态；按允许材料保存可复现内容 |
| 任务条件 | brief/策略的版本引用、用户来源、保留要求、授权和预算引用 |
| 能力范围 | 有资料、可执行、可观察、已验证范围分别记录；真实可用性在使用时再次核对 |
| 评价依据 | 配置先保存，计划随后派生；通过绑定记录关联配置、brief/策略及计划 id/哈希，避免循环哈希 |
| 调用关联 | 各阶段调用引用配置版本/哈希与本阶段职责；现有输入未归档处继续如实标缺口 |

C1 不要求用户填写职业问卷，不靠“资深前端工程师”措辞授予能力，不扩大现有权限、预算或验收范围。

### 一致性与改版

1. 首次使用配置前落盘；必要配置或资源无法核验时，不声称已绑定，也不使用伪造/缺失依据派发相关委托。
2. 计划、诊断、委托与复检取用同一有效配置的相关部分。阶段角色保留，盲评只接收评价所需信息，不接收原诊断答案或组别。
3. 资源注册表之后改变，不得在同一任务中无记录地重新加载不同内容；复用已绑定快照，或记录原因生成新版本。
4. 用户改变目标或授权时重新检查适用性；新版本使受影响旧计划/委托/评审失效，未受影响的适用授权保留。
5. 本轮运行可以在既定条件下调整解决办法；自动优化候选只能用于后续新任务，不能悄悄改变当前任务的标准。
6. 历史运行配置缺失显示未采集，不能回填“当时身份”；旧运行字节与结论不变。

### 验证与交付

C1 开发预算：真实模型/执行器调用 0；用明确 Fake/Mock 捕获各阶段实际发送内容，检查配置绑定、资源变更、目标改版、恢复/复用与盲评隔离。新真实链路验证与 O3 合并，不能把离线捕获称为模型遵循了专业身份。

交付配置可读文件、共用投影/页面按需查看、阶段绑定记录、必要回归和 docs/progress/P2.4-C1.md。技术段通过后停止，交接 O3；是否达到专业水平另行评价。

## 4. 本地浏览器版本（P3.4）

- 发起任务：用自然语言给出目标，展示所选工作区、范围、预算和默认自主推进方式。
- 查看进展：区分计划/模型调用/执行器制作/观察/评审/复检/等待决定，显示依据时刻和缺口。
- 必要介入：答复阻塞决定或主动反馈；通知不要求回复，决定只阻塞依赖动作。
- 看结果：直接打开并操作实际作品；失败时保留已生成产物入口与状态说明。
- 看变化：对照真实版本、相同视口的截图及文件变化；没有变化如实显示。
- 看依据：默认摘要，展开专业配置、观察、委托和复检；不展示内部推理。
- 保持任务：刷新、重连和重复提交不重复派发；关闭页面不丢记录。暂停请求、执行停止与文件回滚各自说明。

写操作通过已有协作服务和状态机，复用 O1—O3 投影；前端不复制验收/授权/预算规则。只提供本机单用户入口，不增加公共部署、产品账号、支付、多租户或管理后台。具备相应前置证据后再接入任务控制。

## 5. 不同任务的适配

共用内核管理目标、来源、权限、预算、委托、观察、修订与停止。按目标和产物选专业资源、观察工具与任务配置；先从已有单页任务族扩展小范围变体，新增类型先核对执行与观察能力。

| 网页变体 | 重点判断 | 需要的观察 |
| --- | --- | --- |
| 活动介绍页 | 信息层级、事实完整与主要行动 | 双视口渲染、内容位置与主要交互 |
| 个人展示页 | 内容组织、图文呈现与导航 | 图片/布局和实际导航 |
| 本地表单页 | 字段含义、操作和错误反馈 | 表单实际交互；没有观察支持就标该维度未知 |

这些是待验证范围，不构成已支持所有类型的声明。用开发案例验证组合，不拿 E1/E2 冻结材料或保留集调参。其他领域后续需新增专业依据、观察和独立评价，共用内核不自动继承专家资格。[领域策略](DOMAIN_STRATEGY.md)

## 6. 自动优化的启动条件与边界

自动优化安排在稳定配置、真实记录和可复核评价之后。启动前需要：开发案例与未见案例按族隔离，评价维度和比较预算固定，独立复核资源可用，质量/回归/成本/用户负担可测，候选版本可回退。

流程：收集失败 → 提出候选配置 → 开发案例对照 → 未见案例及独立评价 → 达到预定门槛后晋升，否则保留旧版。开始研究前再写有界工作包和预算；本大纲不授权后台自改或额外付费运行。

初期研究资源选择、检查清单、提示词、反馈方式；用户目标、权限、预算、硬要求和保留项不由优化器改写。保留同等资源/工具/可比预算的强提示词基线，同样有效时优先简化。模型自评、流程完成和更多调用不能独自证明收益。不在当前范围微调模型或自动发布新技能。
