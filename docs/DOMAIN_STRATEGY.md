# Mentis 首版领域与领域能力组合

版本：v0.3｜日期：2026-09-28｜状态：架构建议，未实现、未验证。用户授权修改规划和研究领域方案，不等于逐项确认下面的新领域选择。

## 1. 首版建议

建议以**小型网页的界面与交互设计**作为首个产品试点。Mentis 担任设计沟通与迭代指导者，执行型 Agent 负责实现。目标用户有自己的想法和审美反馈，但不会写设计任务书。

暂定任务：一个本地单页的活动介绍、个人展示或小产品介绍页；合成文案、已有合法素材；一种主要交互；覆盖明确的桌面和移动视口。不包含登录、支付、生产后端或上线业务。

这是首个验证场景，不是把 Mentis 永久限定为网页工具，也不代表已确定某个网页框架。Mentis 自身聊天界面与实验中生成的网页是两个产品对象。

## 2. 候选领域比较

以下是架构判断，不是市场调查或实测排名。

| 候选 | 与专业指导问题的关系 | 可以观察什么 | 主要难点 | 建议用途 |
| --- | --- | --- | --- | --- |
| 小型网页界面与交互 | 模糊风格、信息层级、体验反馈都能进入修改 | 渲染画面、结构、关键操作、前后版本 | 审美分歧、模型视觉判断需验证 | 首个产品试点建议 |
| 文档问答功能变更 | 便于检查遗漏、权限、引用和需求覆盖 | 输入输出、代码、日志、测试 | 容易偏向工程验收，主观反馈覆盖较弱 | 保留工程回归案例 |
| AI 漫剧/视频 | 与用户最初表达的困难高度相关 | 分镜、关键帧、时间连续性、音画关系 | 生成和观测工具、周期成本、时间维度评审 | 后续先试脚本与分镜，再考虑成片 |
| 室内装修风格 | 普通语言与专业设计之间差距明显 | 图片、布局、尺寸、材料与环境条件 | 真实空间约束、视觉效果与可施工性不同 | 后续限风格探索，不承诺施工判断 |

首版优先选择能够以实际产物检验专业反馈的范围。网页只是当前推荐；若用户选择视频，应明确先做分镜文本还是成片，并重新核对观察工具与评价成本。

## 3. 一次目标体验

用户：“做一个温暖、简洁的咖啡活动页，我不懂设计。布局和视觉你来定，做完给我看。”

Mentis 从已有资料和授权确定目标、硬要求与预算，按专业默认值选择可调整方案，必要时内部比较小样，委托制作首稿。它自行观察双视口和主要交互，发现问题后在授权内给出具体修改并复检，不等待用户逐步回答字体、颜色、按钮等问题。

用户随时可以介入：“有点像促销广告，首图和暖色底保留。”Mentis 对照实际页面检查文案、按钮竞争和信息密度，以证据支持候选解释及局部调整。若用户想参与选方向，再给差异可见的样例；不能强制每个用户走共同设计。

交付附预览、前后变化和检查依据。已检查项与未验证项分开；用户无回复则感受未知。仅当目标重要取舍、用户独有事实或新的权限边界无法自行解决时提出决策请求。本段是设计示例，无实际产物或效果证据。

## 4. 不为每个行业重建工作流

复用三层内容：

1. **通用协作内核**：形成目标、维护委托策略、分流决策缺口、选择动作、委托、观察、反馈、修订、停止。状态、来源、权限、版本和预算共同管理。
2. **可组合的专业资源**：概念与行为映射、判断依据、案例、失败模式、改进方法、评价标准。按当前任务与产物组合，不以职业名称创建完整 Agent。
3. **工具与观察能力**：执行器完成制作；观察器读取实际成果。不同产物需要不同工具，不能假装用一个文本读取器就能评审所有领域。

例如信息层级、视觉风格、可读性可以服务活动页、介绍页和仪表盘；分镜需要额外的叙事节奏与镜头依据。存在可复用部分，也存在不能省略的专业差异。

## 5. 知识从哪里来

| 来源 | 使用方式 | 边界 |
| --- | --- | --- |
| 底层模型已有知识 | 生成解释、候选动作与初步判断 | 不凭自信程度视为已验证 |
| 已审查的能力资源 | 按适用条件加载规则、案例和量表 | 版本、范围、依据可追踪 |
| 当前任务检索材料 | 补充特定工具、材料、标准或情境事实 | 核对来源、日期与相关性；检索成功不等于结论成立 |
| 用户偏好与范例 | 明确此项目的目标和保留项 | 不自动推广为行业标准或跨用户偏好 |
| 真实任务反馈 | 记录有用/无用指导和回归 | 进入待复核案例，不能自动发布新规则 |

初期不追求覆盖所有行业。只维护首任务族需要的少量判断依据，允许后续从任务中补充。新资源可以由模型起草，但审查与评测状态必须保留。

## 6. 最小能力资源模型

资源可以先是 Markdown 加少量结构化元数据，不开发注册中心、插件市场或复杂本体。

| 字段 | 作用 |
| --- | --- |
| id / version / provenance | 身份、版本、来源和维护者 |
| applies_to / excludes | 适用任务、产物与明确不支持范围 |
| decision_questions | 本资源帮助作出的决定，不等于发给用户的问卷 |
| decision_ownership / defaults | 哪些可专业自决、可查证或试验；默认值、适用边界及必须升级的条件 |
| principles / criteria | 规则及性质：硬约束、经验建议、偏好或待验证假设 |
| examples / counterexamples | 有情境的正例、反例、错误与修改方式 |
| observation_requirements | 需要看到哪些真实材料、视口、操作或时间片段 |
| feedback_patterns | 从现象到检查，再到修改的候选路径，不是固定答案 |
| evidence_and_eval | 哪些案例被评估、评价者、结果、失败及限制 |

首版组合可以仅有：信息组织、视觉表达、基础网页交互，以及按需引用的可核查要求。资源数量随已观察问题增加，不靠数量体现专业度。

## 7. 如何切换领域

1. 从目标、预期产物和现有材料提出所需能力，而不是只看“装修”“导演”等关键词。
2. 若存在会改变任务形态的歧义，先查已有上下文和委托策略。可逆低成本探索由 Mentis 自行选择并标注；只有会实质改变目标、成本或权限且无法消解的歧义才请求用户决定，例如脚本与成片的交付范围。
3. 从小型注册表读取元数据，按需加载相关资料与例子。未知任务可检索资料，但记录其候选状态。
4. 核对执行端和观察端分别能做什么。能生成某个文件，不代表能评审其质量。
5. 根据任务构成评价办法，区分硬要求、专业建议和用户偏好；无可用检查时缩小到可验证的交付物或寻求外部判断。
6. 把选定资源、版本和适用范围保存为本次 CapabilityContext。继续使用同一协作内核。
7. 目标变化时重新检查资源适用性，使受影响的委托与评审失效；已授权且不受影响的工作无需反复确认。

跨任务保留通用约束和明确适用的用户选择，不能把“网页要暖色”自动当成“所有视频都要暖色”。切换领域保留委托边界与决定来源，不自动扩大权限；不受影响的专业决定仍可自主推进。切换领域不自动中断无关工作，也不让两个执行器同时写同一工作区。

## 8. 能力范围不能靠路由自证

每个任务分别记录：

- 有哪些资料，哪些未经复核。
- 当前能执行什么，哪些依赖工具尚未可用。
- 当前能观察什么，哪些质量维度不可见。
- 曾在哪些任务和配置上验证，哪些失败仍未解决。

界面可以显示“试验范围”“有限验证范围”“仅能辅助讨论”。这些描述必须对应证据，不能用模型自评或完成固定数量案例自动授予专家资格。

首版的验收包括未知领域识别与受限处理，不包含未知领域自动胜任。高后果专业工作即使找到资料，也不能因此自主作出未经验证的结论。

## 9. 如何证明不是 Persona / Prompt 集合

资源应影响实际行动和检查：观察失败时不能接受；规则有适用条件；评审关联真实产物；反馈记录修改结果；工具权限由内核管理。文件即使使用 Skill 类格式，也只是知识交付形式。

对照实验给强基线同样资料与工具，比较有无动态选择与反馈记录时的表现。若强提示词已经同样有效，应简化架构，不通过增加模块制造差异。

可以参考 Agent Skills 的可组合资源与按需加载方式，但这只是组织方法，不等于专业能力保证。[Anthropic 的设计说明](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)

## 10. 首版实施及后续迁移

P0.4：保留六类反馈链案例设计——模糊目标、小样后形成偏好、含糊不满意、局部修改与保留、已合格应停止、修改引入回归。另增加自主完成、必要介入、撤回三类，合计九类十一实例。每例有可见输入、产物或事件材料要求及独立评分依据；尚未创建真实产物，不冒充案例运行。

P2.1：仅实现小型注册表、适用性检查和首试点资源；P2.2/P3.1 核对实际观察链；P3.2 验证一次真实修订；P5.2a/P2.4 尽早检查系统能否减少用户负担、在必要时介入并接受纠正。

P4 验证两个执行器，不把它称为领域迁移。完整 MVP 后，可选用“讲解型短视频脚本与分镜表”检验新增专业资源、无需重写核心的程度。需记录人工定制时间、新工具、核心改动与失败。没有第二领域实测，就不宣称跨领域能力已验证。

## 11. 评价依据与限制

网页硬要求可以按具体任务参考 [W3C 无障碍快速参考](https://www.w3.org/WAI/WCAG22/quickref/)，但自动检查或若干条规则通过不代表完整无障碍合规，更不代表作品审美优秀。

评测同时保留任务轨迹和真实结果，避免把执行器总结当成完成证据。[Anthropic Agent 评测说明](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)
