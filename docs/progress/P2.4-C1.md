# P2.4-C1 进度记录：最小任务专业配置冻结（2026-10-08）

性质：按[本地产品大纲 §3](../LOCAL_PRODUCT_ROADMAP.md) 实施的 P2.4 内部补强。范围：任务级专业配置（职责/资源快照/任务条件）先落盘、同任务阶段同一有效版本、更新有原因且旧版本不改写、盲评隔离保持。**真实模型/执行器调用 0**；真实链路核验按计划与 O3 一次登记预算的真实任务合并。技术段通过后停止，交接 O3；是否达到专业水平另行评价（配置只解决一致性，不授予专业资格）。

## 1. 起始事实与范围核对

- 起始状态：O1/O2 完成后的工作树（未提交改动全部保护，不打包提交）；本轮起始包含 O1—O2 的 13 个修改文件与 12 个未跟踪文件。
- [O3 页面记录 §6](P2.4-O3-page.md)核对出的缺口：collab 在计划与诊断阶段分别调用 `select_for_task(load_registry())`，注册表/资料未绑定到同一份不可变任务快照；没有贯穿任务的统一配置。
- 本轮只做 C1；不改 E2 费用候选映射、授权/unknown/验收/预算规则；E1/E2 冻结材料与历史运行字节不动。

## 2. 实现

- **新模块 `mentis/professional.py`**（`mentis-professional-config/1` + `mentis-config-binding/1`）：
  - `ConfigManager.ensure()`：首次调用做**一次**资源选择（决策需要取 collab 计划层/诊断层的并集），把命中资源内容**逐字节快照**进运行目录 `professional-config/resources/`，配置 JSON（六类最小记录：职责、专业依据、任务条件、能力范围、评价依据说明；文件不含自身哈希避免循环哈希）先落盘，随后写绑定行、发事件；
  - 同任务复用同一版本；brief/目标变化 → `revise()` 生成新版本（reason_kind=goal_change/brief_revision），旧版本文件字节不改写；未受影响的授权保留（session 授权不动）；
  - 注册表内容漂移 → 每资源至多一次 `professional_config.drift` 事件，**继续使用快照**，不静默换内容；
  - 恢复/续办：新实例从运行目录读回配置，核验配置哈希（对 bindings）、资源快照哈希（对 grounds）；任一不符抛 `ConfigPersistenceError`——依赖配置的计划与委托不发起（与 V1 PlanPersistenceError 同一 fail-closed 模式）。
- **三入口接线**：collab（`_ensure_evaluation_plan` 配置先于计划落盘、诊断复用同一上下文、委托/诊断/处置/复检阶段行绑定配置）、guidance（同型）、eval-run（M 臂 `_plan_for`/诊断/盲比走同一管理器；**B-1 基线臂不使用配置链，保持不记录**，投影如实显示未采集）。
- **调用与阶段关联**：`trace/model-calls.jsonl` 行可选 `config_version/config_sha256/stage_responsibility`；`trace/stages.jsonl` start 行可选 `config` {version, sha256}——仅提供时写入，历史行不回填。
- **盲评隔离**：`run_blind_review` 输入仍只有计划标准与前后观察；配置仅以关联信息写入结果 JSON `professional_config` 字段（版本/哈希/本阶段职责），不含资源内容或诊断结论（有测试断言提示词中无配置规则文本）。
- **共用只读视图**：`load_professional_view`（run_projection）供投影 Markdown「专业配置（C1）」节、`mentis status` 状态行、conversation 事件节（`professional_config.recorded/.revised/.drift/.blocked` 按真实顺序）与页面「专业配置」面板共用；recorded/unverified/unrecorded 为展示标签，不是业务判定。

## 5. Mock、未完成与限制

- 夹具运行是**离线 Mock**（FakeAdapter 写固定页面、无模型调用）：证明的是配置冻结/绑定/恢复/fail-closed 的离线逻辑，**不能称为模型遵循了专业身份**。
- 本轮真实模型/执行器调用 **0**；配置链在真实委托运行上的表现（含 B-1 未记录的对照）待 O3 一次登记预算的真实任务核验。
- 职责文本与"不支持范围"是**程序预置并逐条标注来源**；资源复核状态为 pending_human；配置不消除"未验证"能力边界，不构成专业资格声明。
- 计划/诊断决策需要取并集（原诊断层的"视觉层级"与计划层的"促销感来源"合并为一次选择）——选择输入从此任务内不变，这是行为修正而非纯新增；离线回归 341 项通过表明既有行为未破坏。
- `mentis eval-plan` CLI（只读计划预览器）仍按原逻辑直接选择资源，未接配置链（预览器不委托、不产生运行目录）；如后续需要预览也带绑定再改。
- 历史运行（O1/O2 及更早）不回填配置：三个视图如实显示未采集；心跳/阶段等既有未采集语义不变。
- O3 真实任务、T4 本人体验、E2 独立评审、专业效果分别保持各自真实状态，本轮不改。
