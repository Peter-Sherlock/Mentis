# 修订（2026-09-27 第二轮，负责人初审后）

## 负责人初审结论

用户审阅实际文件后判定：**案例草案已交付，评价设计需修订后再通过 P0.4 验收**。肯定项：六类案例齐全、四视图齐备、草案标记诚实、无虚构调用/复核/作品、结构复查无问题。四类必须修订的问题：

1. **运行输入泄漏答案**：FC-06 运行输入写明回归（移动端溢出、首图被替换）却要求评测自主发现；FC-05 运行输入写明"已满足硬要求、无缺陷"。结论性内容必须移入作者/评测侧，运行端只拿原始作品、真实反馈与观察工具。
2. **FC-02 用户卡与自由生成样例无衔接**：卡内固定"A 暖棕/B 几何、选 A"，但系统可自由生成不同方向或顺序。需分固定样例（查偏好记录）与自由生成（按实际内容选择）两种模式；模拟选择不得当作真实审美体验。
3. **FC-03 端到端强行预设失败**：不能无论首稿好坏都反馈"像促销广告"。固定缺陷首稿只用于反馈实验；端到端反馈必须对应实际产物。
4. **评分与对照不够具体**：缺一致判定示例（字段写齐≠指导有效）；反馈实验中 B-0 与 B-3 近似，需区分或合并。用户同时指出此点反映原规划本身需继续细化，不全部归责执行 Agent。

用户并要求建立**每轮可观察交付**制度（详见下文文档变更）。

## v0.3 追加修订（2026-09-28）：自主委托的案例与评价

### 历史和状态口径修正

上文保留 v0.1/v0.2 的交付、问题及当时状态，不能作为当前状态。前轮将用户转述的审阅意见记为“负责人初审”，该记录不足以证明独立专业人工复核；本轮没有新增这类证据，全部现行案例继续 pending_human。

本轮用户授权规划调整，包含其案例与评价要求的同步。文档工作包的退出条件与案例专业复核分开：完成可审阅设计及相称检查即可记录文档交付；人工专业复核仍约束正式效果结论。取消“每次修订后必须再问用户验收才可继续”的额外审批门槛，不取消用户控制权或真实工程范围约束。

### 交付变更

- FC-01 允许专业默认值直接出首稿，不强制先问或先让用户选样例；FC-02 保留用户主动要求共同设计的路径。
- FC-03 将保留偏好的实际原话纳入运行输入，候选成因不冒充因果证明；无回复时感受未知，不强制确认。
- FC-04 双视口已有要求，重复询问计不必要介入；FC-05/06 清除运行输入中的案例目的提示。
- FC-06 显式提供原保留项、双视口及修订预算的会话依据；授权内修复自主执行，不用用户好评代替复检。
- FC-07 检查无中途回复的委托；FC-08a/b 检查重要事实冲突与保留授权，并要求配对的可自主处理条件；FC-09 检查撤回、在途执行与旧结果。
- 合计九类十一实例，每例四视图。文件哈希不能替代实际渲染保留检查；固定样例可在 Git 基线后手工制作供早期观察，但不算真实执行器证据。
- 评价加入不必要介入、必要介入覆盖、自主完成及决定归属，明确分母、N/A、机会去重和质量前提；模拟通知不触发自动用户回复。
- 保留 B-0 仅用于端到端、反馈实验 B-1/B-2/B-3/M；不人为削弱强提示词基线，默认委托与共同设计分别分析。
