# P2.4-T1 验收修复：追踪完整性与决策回放

日期：2026-09-29｜状态：**completed（T1 范围内修复；T2 未开始）**

## 起点与范围

对 T1 的只读审查发现四处可复现的审计缺口：事件文件末尾半行会吞掉续接后的完整事件，但 manifest 仍显示完整；恢复时委托终态、thread ID、用量丢失；回放只展示存储的哈希，不核查引用文件的当前内容；指导流程的用户请求及自主分流没有追踪事件。用户要求直接修复。本轮仅改 T1 追踪与测试，不触发 DeepSeek 或 Codex，不进入 T2 逐行流。

## 变更

- `mentis/trace.py`：续写前隔离半行，保留坏行作为证据；manifest 收尾从磁盘重扫事件可读性、seq 连续性、契约与 run_id，区分可读事件数与最大已占用序号，历史写失败在恢复后继续标为不完整。
- 执行器终态事件增补可选的原始终态与结构化用量；恢复时优先从事件重建委托台账。旧 T1 事件无结构化用量时，仅在同 run、同契约、同 prompt 指纹下继承旧 manifest 的终态资料；没有可靠来源时保持未知。
- `mentis trace --run` 现读重验事件流与每个 `refs` 的文件哈希；引用缺失、哈希不符、事件损坏或 manifest 不完整均显示“当前核验：未通过”。落盘 manifest 状态与当前核验分开展示。
- `mentis/guidance.py`：用户决策请求、请求路由、自主分流、用户回答及 brief 更新进入事件流；回答原文仍留在会话记录，事件只写交互 ID 与版本。`mentis/collab.py` 与 guidance 均写结构化执行器终态/用量。
- 契约 §2/§11 和当前开发状态同步记录字段及语义变化。旧历史运行依然只读列缺口，不回填事件。
