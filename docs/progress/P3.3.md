## 2. 真实缺口修复（先于真实运行，全量回归通过）

覆盖审计发现三处缺口集中在"进程中断"路径，另补两处留痕：

1. **委托发起即落盘**（`_dispatch_codex`）：原先 dispatch→mark_running 后直到适配器阻塞返回都不落盘，进程中途被杀时在途尝试只存在于 trace 与写锁中，恢复后的会话看不见它。现在委托发起即 checkpoint 落盘（`_persist(..., checkpoint=True)`，不发 `run.finalized`）。
2. **thread.started 凭据早记**：执行器线程 ID 原先等适配器返回才记录；现在 `thread.started` 事件一到即写入 `self.thread_id` 并随 executor.started 事件入 trace——进程中断后可从追踪恢复续接凭据。
3. **孤儿尝试核对收养**（`confirm_outcome_after_review`）：running 且无任何执行器结果记录（运行进程中断特征）的尝试按 unknown 纳入核对（`attempt.reconciled` 留痕）；是否仍在写入由既有活跃 codex 进程检查把关。
4. **accept.rejected 留痕**：接受被拒（含过期版本）原先只发通知，现入事件流。
5. `_persist` 增加 `checkpoint` 参数（过程落盘不发收尾事件）；正常路径仍恰好一次 `run.finalized`（回归断言）。

回归：`tests/test_p33_recovery.py` 4 项（崩溃模拟 BaseException 绕过异常收尾 → checkpoint 在适配器调用前已落库、孤儿收养零重发、活跃写入者在场拒绝确认、旧目标晚到确认走真实 `_finalize`→`accept` 链被 StaleVersion 拒、checkpoint 不多发收尾事件）。全量 **381 项（380+1 跳过）**通过（修复后实跑两次：真实运行前后各一次）。

## 5. 诚实边界（未实现/未触达/Mock 清单）

- **StaleVersion 真实链路未触达**：锁协议要求改目标前先核对旧 unknown，旧尝试被迫先转终态；真实链路中晚到确认被硬要求门禁（产物缺失）先拦下。版本门禁本身由离线回归覆盖（走真实 collab/_finalize/accept 代码，Fake 执行器）。
- **"活跃写入者在场拒绝确认"未在真实链路现场捕获**（S1 孤儿在核对前自然退出）；该路径由离线回归覆盖；同型的真实拒绝见 S6（ExecutorBusy）。
- S1 的击杀由驱动看门狗路径触发（检测缺陷→超时→kill）——对被杀运行是真实进程中断，效果与预定注入一致；驱动缺陷（运行目录名秒级截断 vs 微秒 now() 比较）已修复并记录。
- S4 构建轮预期 DELIVERED 实得 UNKNOWN（600s 超时）——撤回语义在等待状态下验证，如实记录。
- 用量口径：S1 执行器用量未取得（孤儿随进程死亡），聚合中的 0 表示未记录；S5 的 3 次 delegation.prepared 中 1 次未实际启动执行器。
- 编排脚本 `run_scenarios.py`/`probe_p33.py` 为进程控制与取证工具，不是产品入口；产品入口仍是 `python -m mentis collab / collab-resume`。
