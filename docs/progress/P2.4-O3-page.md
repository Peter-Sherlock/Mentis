## 2. 实现

- `mentis/run_view.py`：stdlib 本地 HTTP 服务，提供任务目标、原始判定、候选处置、按主体筛选的事件时间线、可展开公开交流、实际调用记录、证据链接与截图。
- `mentis view --run <目录> --port 8873`：每 4 秒检查记录变化，保持展开项与主体筛选。刷新只表示读取新记录，明确“任务进程活动状态未采集”。
- 首稿/结果归档静态对照、绑定后的文本 diff；两版相同则显示“未修改作品”。不把文件变化重新判为 improved。
- 仅绑定 127.0.0.1；拒绝变更请求、外部 Host、未列出或越界文件、失配证据；转义外部文本，HTML 证据和预览禁用脚本/发送。
- 只读页面不读取评分答案或私有 rollout，不启动、续办、取消任务。原始 trace、模型调用、授权、方法判定均沿用 O1。

## 6. 专业身份的代码核对

| 机制 | 当前实际实现 |
| --- | --- |
| 每次角色提示 | `diagnosis.SYSTEM_PROMPT` 定义网页设计指导诊断模块；计划与盲比使用各自阶段角色；网关每次发送 system + user 信息 |
| 领域依据 | `select_for_task` 生成 CapabilityContext、加载资源与规则；诊断 prompt 包含目标、反馈、领域依据和实际观察 |
| 任务连续性 | session 保有 brief、委托策略、决定与版本；授权/保留项由程序管理 |
| 评价标准连续性 | collab 委托前保存版本化 EvaluationPlan 与 SHA-256；同一 brief/目标复用，变更有原因地改版 |
| 验收边界 | 候选映射/路由、真实观察、复检与旧版本拒收约束后续动作；这些机制约束行为，不授予专家资格 |

缺口：没有贯穿任务、统一冻结的专业角色配置。collab 在计划和诊断阶段分别调用资源选择器，注册表/资料未绑定到同一份不可变任务资源快照。当前网页关键词与若干职责为程序预置，不能据此声称已经实现任意领域专家切换。

后续建议（未实施）：保存任务级角色/职责、资源版本及内容哈希、判断范围、观察能力、授权边界、评估计划引用；每次阶段调用关联同一配置版本，变化时记录原因并使受影响的旧评审失效。阶段角色可不同，盲比继续只接收标准与观察，不灌入原诊断结论。固定配置只解决一致性，专业水平仍需作品对照与独立评价。
