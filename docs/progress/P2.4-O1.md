# P2.4-O1 记录：统一记录与可读回放（2026-10-08）

性质：按 [O1 开发 prompt](../prompts/P2.4-O1.md) 实施的一轮开发。范围只含 O1；O2（阶段/等待/活动状态）与 O3（只读页面 + 一次真实任务核验）未实施。

## 1. 本轮目标与结果

**目标**：统一 collab / guide-revise / eval-run 的公开消息采集；补齐 conversation 中的评估计划、观察、诊断与决策回放；建立 CLI 与后续页面共用的只读运行投影；同一真实 E2 样例可连续追溯。**真实模型/执行器调用预算 0（实际 0 次）。**

**结果**：完成。离线回归 293 项通过（新增 20 项针对性测试）；真实 E2 运行 `20261004_055316-937e-input-002-M` 的新视图可连续看见「费用缺失 → 模型候选 → 程序因 0.082 判计划盲区 → 零委托 → no_change」；读取前后该运行 74 个文件逐字节一致（历史判定不改写）。

## 2. 变更清单

### 统一采集（三入口同一实现）

- `mentis/trace.py`：新增 `bounded_text`（摘要首尾保留：≤160 字，超出时头部+「…（中略）…」+尾部 40 字——中文长消息尾部不再丢失，T4 缺口）与 `describe_executor_event`（共用采集逻辑）。`agent_message` 全文归档 + `role=executor_message` 哈希引用 + 「全文已归档」摘要；归档失败摘要显式标注「全文归档失败：追踪完整性缺口」；`command_execution` 状态明确（completed/failed/in_progress，缺失 unknown）且标「输出未采集」；`reasoning` 只记类型；采集异常降级为「事件采集异常」占位并经 `note_capture_failure` 计入完整性——不静默吞掉。
- `mentis/collab.py`、`mentis/guidance.py`、`mentis/eval_runner.py`：三处 `on_executor_event`/`on_event` 全部改为调用共用逻辑（eval-run 此前缺全文归档，本轮补齐）。

### 模型调用 sidecar（新运行起）

- `TraceWriter.record_model_call` + `trace/model-calls.jsonl`（`mentis-model-call/1`，追加式）：request_id、model、created_at、latency_ms、ok、usage、error、mock、http_attempted、prompt_sha256、image_refs、**stage**（plan_instantiation / diagnosis / blind_review，由调用点声明）、output_refs；`input_text_archived=false` 显式标记输入全文未保存。写入失败计 `write_failures`（`events_complete` 随之为 false）。
- 三入口在计划实例化、诊断、盲比各点声明阶段并记账；collab/guidance 恢复对象只记恢复后的调用（恢复前 unrecorded）。

### 交流视图补齐

- `render_conversation`：按 seq 顺序新增评估计划（含计划文件+SHA-256）、观察、诊断（含诊断全文引用）、处置决定（decision.routed）、用户决定（requested/answered）各节；零委托运行明示「0 次委托……不为展示交流补造执行器消息」；判定值不在事件摘要时从 runner-state/state.json 确定性读取并标注来源与「原判定不改写」。

### 只读运行投影（CLI 与后续页面共用）

- 新模块 `mentis/run_projection.py`（`mentis-run-projection/1`）+ CLI `mentis replay --run [--out]`：
  - 决策记录：模型提案（现象）→ 程序处置（决定、理由、映射方式与得分、后续动作）/ 用户决定分列；来源只按现存文件确定性读取（eval-run 读 runner-state.summary.candidates，collab 读 professional-review.json，guidance 读 state.json 轮级记录），不重算映射、不改判定。
  - 模型调用：优先读 O1 sidecar；历史 eval 运行按 runner-state.model_requests 读取（模型名/时刻/耗时/输入哈希 unrecorded；只有计划实例化可用量精确匹配关联，其余如实标「关联未记录」）；O1 之前 collab/guidance 只有缺口清单。
  - 版本与证据：评估计划/产物/截图/测量/复检记录，哈希现在计算并与事件 refs 比对——一致 verified；不匹配/缺失/**越界** unverified（越界引用不读取，内容不进入投影）。
  - 记账分列：模型调用数 / HTTP 实发数 / 执行器委托数；未知用量不写 0；不虚构货币成本。
  - 无事件流的历史运行：「委托数 unrecorded」，不冒充「零委托是真实行为」。
  - `--out` 拒绝写入运行目录内；投影只读、可再生成。

### 契约与文档

- [追踪契约](../TRACKING_EVENT_CONTRACT.md) 新增 §17（O1 附录）：无新增事件 kind/字段，记录采集统一、sidecar、conversation 补齐与投影四项增补。
