## 隔离轮追加记录（2026-10-01 第二轮）

本轮完成负责人指定的单步：受测 Mentis 与 Codex 的真实读隔离，并把验证结果接入运行前检查。

### 变更

- 新增 `mentis/eval_isolation.py` 与 `eval-isolate probe|release|check`：
  - 隔离窗口 = Windows deny ACL（`icacls /deny`），对当前用户与 Codex 沙箱账户（CodexSandboxUsers/Offline/Online，存在才加）在**同一次 icacls 调用**内写入 deny。deny 生效后第二条 DACL 写句柄会被自己拒绝（实测退出码 5），因此必须单次调用。
  - 开窗前金丝雀预检：在目标同父目录新建 `_iso-canary-*` 先走一遍 deny→验证拒读→release→验证恢复。该预检来源于实测发现的陷阱——Python 3.14 `tempfile` 根带 `OWNER RIGHTS` ACE，其下目录被 deny 后属主隐式 WRITE_DAC 一并失效，同用户将无法解除。
  - 受保护清单：套件目录（防 sample 身份推断）+ prepare-report.json（身份映射）+ 除目标组外全部输入包。
  - 双端真实探测：Mentis 端以同一解释器/用户/cwd/env 在工作区副本运行探测脚本（正向读+写、反向绝对路径/`..` 父目录遍历/junction 三类）；Codex 端经真实 `CodexCliAdapter`（workspace-write + approval never）委托探测任务，判定只依据其在工作区留下的 denied-N.txt/read-N.txt/positive-write.txt 标记，自由文本仅存档。
  - 准入 `check_admission` / `eval-check --isolation-evidence`：核对证据存在与 schema、保鲜期（TTL 12h）、whoami 身份一致、Codex CLI 版本一致、双端探测无问题、**当前 live 拒读实测**。任一缺失即保持未就绪；窗口关闭（released_at）或证据过期立即失效；窗口关闭后用 suite_sha256 与当前磁盘 audit 闭环，不一致写入 blocking_reasons。
- 适配器修复（真实运行触发的缺陷）：`codex` 为 npm `.cmd` shim，CreateProcess 不查 PATHEXT，裸名启动 FileNotFoundError（早期实验实际发生）；含 ASCII 双引号的多行 prompt 经 shim `%*` 重解析会被截断（探测中 Codex 只收到第一段）。修复：启动路径 `shutil.which` 解析为绝对路径（仅真实路径，注入 runner 的离线测试不受影响）；prompt 一律经 stdin（官方 `-` 约定）传递，T4 的多行 prompt 当时能走通是因为不含双引号——这是潜在缺陷而非当前行为退化。
- `docs/evaluation/e1` 属主归一化：该树多为 `CodexSandboxOffline` 所有（E1 页面经 Codex 沙箱生成），WY 无 WRITE_DAC 无法开窗。处置 = 删除后 `git checkout` 恢复，suite sha256 `7fe7365c…` 与 26 份冻结源哈希核验不变（`.gitattributes -text` 生效）；未改动任何字节内容。

### 实际验证（真实环境，非夹具）

- 开窗后同用户子进程：21 个验证点 × 3 形式（绝对路径/父目录遍历/junction）= **63 次反向读取全部 PermissionError**；正向 input.json/prompt.md 可读、工作区可写。原始输出：`runtime/evaluation/e1-isolation-probe/isolation/probe-20261001_085257/mentis-probe-stdout.txt`（含逐条记录）。
- 真实 Codex CLI 0.158.0（workspace-write）：9 次读取尝试（3 文件 × 3 形式，含 junction）全部 DENIED，denied-1/2/3.txt 与 junction-1/2/3、positive-write.txt（OK）留存在工作区；未读取到任何内容（read-* 为零）。原始输出：同目录 `codex-probe-response.txt`、`codex-probe-events.json`、`codex-probe-result.json`。用量 input 256,423 / output 3,783 tokens（无货币硬上限，仅记录）。
- 窗口内准入：`eval-check --isolation-evidence …` 返回 `runtime_answer_isolation.passed=true`（8 项全过，含 live 拒读）；`eval-isolate release` 后同一证据立即失效（passed=false），普通 `eval-check` 冻结哈希仍通过（闭环一致）。
- 4 次失败尝试的原始输出保留在 `isolation/probe-20261001_08{2449,3040,3600,3846}`：ACL 属主问题 → codex 裸名启动失败 → 探测说明被当铺垫未执行 → 双引号截断。每次失败窗口均自动解除、不写证据。
- 191 项离线测试通过（新增 22 项：真实 ACL 窗口/释放、无效 deny 必失败、双端判定、证据过期/身份/版本不一致、窗口关闭失效、金丝雀拦截、探测流程失败不留窗口）。

### 失败、限制与未完成

- deny 不防对抗性绕过：同用户属主保留 WRITE_DAC，可自行解除 deny。与"独立运行身份"的差距如实记录；当前威胁模型是意外读取（绝对路径/上级目录/junction），非主动越狱。
- 早期实验在 %TEMP% 留下 8 个被锁小目录（OWNER RIGHTS 世系，仅含合成数据，非仓库内容）；非提权无法解除，需管理员或系统清理。真实 apply 流程已被金丝雀预检保护，不会再产生。
- Codex 端探测为代表性覆盖（3 个验证点：答案文件/身份映射/他组 input.json）；Mentis 端覆盖全部 21 点。准入 live 检查只验证文件拒读，不构造 junction。
- 探测证据不证明：提示词服从、模型不试图读取、样本未被语义泄漏污染（导出字节一致性此前已核，语义无泄漏仍无证明）。
- E2 运行器、预算执行、共享追踪、正式指标与独立人工复核仍未实现/未完成；本轮无任何效果结论。T4 体验保持 partial，负责人五问仍未由本人回答。
