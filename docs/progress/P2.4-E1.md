## E1 收尾：公平运行器（2026-10-02 第四轮，基线 e25f149）

按开发计划 E1 收货行实现 `mentis/eval_runner.py` + CLI `eval-run`：同一冻结输入包上运行受测 M 与基线组（B-1 等），隔离窗口内、共享追踪（trace 契约）、执行预算逐项执行（3 委托/2 修订/4 外层模型调用/600s 每 turn，来自 suite policy）。

### 机制

- **准入 fail-closed**：运行前 `check_admission` 强绑定 prepared_dir/target_arm/suite_sha256 + 身份 + 探针版本 + 执行器版本 + 双端原始记录重验 + 当前 live 拒读；任一不通过抛 AdmissionError、执行器零调用（有测试）。
- **包展开一致**：`_flatten_package` 把 arm 包展开为运行工作区（workspace/* 到根 + input.json/prompt.md/input/resources/observation 并列），两臂同一规则逐字节一致（有测试）；git init 提交冻结基线。
- **基线臂（B-0/B-1/B-2/B-3 通用）**：prompt.md 驱动的执行器循环，预算内委托（completed 停 / unknown 停不重发 / failed 预算内续办同 thread）；无外层模型调用；确切指令先落盘（哈希=发送）。
- **M 臂**：V1/V2 全链路——评估计划先落盘（模型实例化）→ 观察（结构+渲染测量+双视口截图）→ 真实诊断 → 守卫链+可验证性路由（与 collab 同语义）→ 采纳项修订指令（含计划验收项）→ 重观察 → 确定性复检+盲比（两序）→ 判定分级；端到端样本先按计划派生验收项委托构建。预算：盲比内部两序请求计 1 次复查预算；耗尽如实收尾 unverified 不冒充。
- 每臂独立隔离窗口（probe→run→release，各自 target_arm 绑定）；manifest（run-manifest.json，mentis-eval-run/1）记录预算用量/用量/产物哈希/判定，trace/events.jsonl 全程事件。

### 已观察发现（记入 E2 设计输入；本轮不改运行器）

1. **M 臂映射同义词缺口**：真实缺陷候选"费用信息缺失"被词面映射判为计划盲区 → M 未修复缺价，而 B-1 修复了。这是 M 方法（含其路由启发式）的真实行为；**看到该结果后调优映射会污染对照**，故本轮不改。E2 报告须把它列为 M 的观察项；若 E2 前修映射，须作为新版本另存并记录理由（ADR-008 §5 同等纪律）。
2. **600s per-turn 预算对 B-1 自检循环偏紧**：B-1 的"多轮自检+修订"完整流程在一个 turn 内超过 600s——预算如实执行（树杀+unknown），但"turn 切分/续办协议"（unknown 后预算内续办 vs 重跑）是 E2 运行协议必须先冻结的决定。
3. d3 候选的溢出守卫驳回提示：诊断 joined 文本中偶发"溢出"字样即可触发守卫，需要 E2 观察其误伤率（与 P2.2 语义筛选误差同账）。
