## 1. 实现

### 1.1 新增 `mentis/eval_review.py`

- **候选→维度确定性映射**（`map_candidate_to_dimension`）：显式维度 id 引用（如 "T1"）直接命中；否则按词面重叠（中文二元组+ASCII 词）取最高分维度（阈值：共享≥3 且覆盖率≥0.12）。映射是启发式——命中方式与得分逐条写入审查记录供审计。
- **按检查方式路由**（`route_by_verifiability`，ADR-008 第 6 条）：`deterministic / pairwise_blind` → 可自主修订；`user_judgment` → **非阻塞选项**告知用户（不自动修改，触及保留决定仍走 request_decision）；`unverifiable` → 不修订、不据此宣称改善；对应不到任何维度 → **计划盲区**，不自动采纳（可按 ADR-008 第 5 条程序提出修订，不自行动）。既有守卫次序不变：保持现状 → 溢出对照测量 → 保留决定 → 可验证性路由。
- **盲比复检**（`run_blind_review`，ADR-008 第 7 条）：修改前后两版观察（结构文本+渲染测量+双视口截图）随机标为版本 X/Y（`random.Random` 可注入，生产真随机）；**只给计划中的标准条目**（`blind_review_standards()`：deterministic/pairwise_blind/user_judgment 且非 hypothesis），不给诊断理由与修改指令；正反两序各判一次；逐维度正反一致化——两序不一致或 cannot_judge → 该维度 unknown；总体两序不一致 → `inconsistent`（不判改善）。虚构维度编号剔除并留痕（`dropped_refs`）；调用失败/输出非法 → `unknown`；观察包缺失 → 直接 unknown（不臆测）。输出落盘 `blind-review-*.json`（含随机指派、两序原始判定、逐维度结论、用量、Mock 标注）。
- **判定分级**（`grade_revision`，ADR-008 第 8 条）六值：`regression`（回归优先）→ `unverified`（观察不可信）→ `no_change`（产物未变/盲比一致判无正向变化）→ `improved`（盲比两序一致 after_better，或目标维度两序一致改善）→ `changed_unverified`（两序不一致：改了但效果未验证）→ `unknown`（盲比缺失/无法解释）。**同源模型盲比降低确认偏差，不建立独立性**（PROJECT_PLAN §16.5），逐处标注。

### 1.2 collab 接入（`mentis/collab.py`）

- `_adjudicate_candidates` 改为可验证性路由：每条候选记录 `dimension`（映射维度）、`matched_by`/得分；新决策 `user_option` / `skip_unverifiable` / `plan_blind_spot`；`adopt` 仅当映射到 deterministic/pairwise_blind 维度。审美/偏好类与盲区候选以 notify_progress 非阻塞告知（不等待、不新增审批）。
- 修订复检：`run_model_review`（非盲"问题是否仍存在"）替换为 `run_blind_review`；`professional-verify.json` 记录 `blind_review`（overall/consistent/逐维度/随机指派/用量/mock）与 `verdict`/`verdict_basis`；trace `review.recorded` 携带盲比结论与盲比文件哈希。
- **验收门与判定分级解耦**：接受门=确定性健康（无回归、观察可信）；盲比只决定"改善声明"——`changed_unverified/no_change/unknown` 如实交付但不宣称改善（报告与交付说明逐处标注）。回归仍不交付（快照保留）、观察不可信仍 UNVERIFIED 不判通过。
- 报告"看结果"逐维度列出判定（改善/变差/相当/无法判定），"看依据"含 `blind-review-professional.json`；审查记录 `source_note` 与 `routing` 计数更新。
- **真实运行发现并修复**：unknown 人工核对路径的存活门控曾被 IDE 常驻进程误伤（`codex.exe app-server`、`codex-computer-use` 以 codex 之名常驻，非委托写入者）——`_codex_processes_since` 改用 CIM 命令行过滤排除这两类（配 2 项离线测试）；其余 codex 进程仍一律视为潜在写入者。

### 1.3 guide-revise 接入（`mentis/guidance.py`）

- `_ensure_evaluation_plan`：冻结基线后、首次修订委托前落盘 `evaluation-plan/plan-v1.json`（brief=冻结目标/约束，素材=基线 workspace_input_copy.md，领域资源同源加载；模型实例化随 use_model，失败降级标注）；落盘失败抛 `PlanPersistenceError` → 修订委托零发起；`evaluation_plan.recorded` 事件按契约记录。
- 修订指令尾部追加计划派生的"本轮验收项"（归档哈希=实际发送）；复检 `_verify_round` 改为盲比（round1 前版=当轮修改前观察；retry 轮先观察部分产物作为"修改前"基准；恢复路径 `guidance_from_state` 重载已落盘计划）；判定分级同 collab。
- `--reverify`（历史轮次透明更正）：优先复用**已绑定当前 v2 哈希**的盲比判定（`reviewed_after_sha256` 比对，不新增模型调用）；无盲比文件的旧运行走原 legacy 绑定路径（图像指纹+测量 sha 间接绑定，测试合成旧格式记录覆盖）；绑定不符 → `review-unbound` 不复用、判 UNVERIFIED。
- 判定值进入轮次记录与报告（`CHANGED_UNVERIFIED` 等新状态字面量直接呈现）；候选路由本身仍属 collab 的候选审查步（guide-revise 无候选审查环节，其"每轮全部诊断直接修订"的预算内流程未改，见 §4 边界）。

### 1.4 未改动

权限规则、ADR-002 默认自主、预算与单写入者语义、`docs/evaluation/e1/` 冻结字节、T4 历史运行目录、E1 隔离基础设施。追踪契约无新增 kind（盲比结论经既有 `review.recorded` + refs role=review 记录；随机指派等细节在盲比文件中，事件摘要携带关键结论）。

### 2.2 真实核验 1：历史运行新规则重判（`runtime/v2-rejudge-73ca/`，原目录只读未改写）

## 5. 失败、限制与观察项

- E2E 构建委托 420.7s 超时 → UNKNOWN（真实再现 P2.3 架构限制）；核对路径因 IDE app-server 门控误报被阻一次，已修复（§1.2）并留测试。该限制的异步/分段策略仍留待 P3.3。
- 候选→维度映射是词面启发式（阈值 0.12/3 共享），重判中 d2 得分 0.129 临界命中——映射误差会直接改变路由，列为 E1/E2 观察项（与 P2.2 语义筛选误差同账）。
- 盲比"equal"结论依赖模型对标准的一致判断；重判中 D-A 维度两序均 cannot_judge → unknown（诚实但意味着审美维度盲比常不可判——与"user_judgment 归用户"的设计一致）。
- 跨进程用量分账（计划 vs 诊断）分别记录于不同文件，汇总需人工相加；不做虚假合计。
- T4 五问独立回答仍待负责人；E1 公平运行器与 E2 对照未开始。
