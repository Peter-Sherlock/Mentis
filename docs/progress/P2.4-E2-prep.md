## 1. 审计失败定位（结论：环境限制 + 两处相邻真实缺陷已修）

### 1.1 UNVERIFIED 替代 DELIVERED = 设计行为，触发原因是审计 shell 的浏览器限制

- 离线全量套件在本机完整通过（235 项），套件内无任何真实浏览器调用（截图/测量均注入替身）——该失败不可能来自离线测试，必来自真实流程复现。
- **本机全权限 shell 真实复现成功**：对冻结样本 E1-02 运行 `measure_page`（真实 Chrome 154 无界面双视口），mobile inner_width=390 / desktop 1280、双视口溢出 0px、错误 0——测量链路在本机完好（证据 `runtime/e2-prep/measure-repro2-output.txt`）。
- 浏览器**异常退出**时（受限 shell 的典型表现，E1 准备轮已有同现象先例："初次本地Chrome受沙箱限制退出"），`measure_viewport` 逐视口记账"浏览器退出码 N"→ 观察不可信 → 修订后复检判 **UNVERIFIED、不交付**。这正是 P3.2 验收修复确立的"测量不可信→不判通过"按设计生效，**不是误判，未放宽任何规则**。
- 真进程复现测试：新增 `test_real_abnormal_browser_exit_yields_unverified`（用 python.exe 充当必然异常退出的"浏览器"，真实子进程、零 Mock），完整复现审计路径：修订→复检测量异常→UNVERIFIED、不接受、verify 文档 `measurement_unknown=true` 且逐视口含"退出码"错误。

### 1.2 顺带发现并修复两处真实缺陷（不改变验收规则）

1. **浏览器无法启动（OSError）未记账**（`render_measurement.measure_viewport`）：沙箱禁止进程创建时 `subprocess.run` 抛 OSError，此前会炸穿观察链到 collab ERROR 收尾（manifest/run.finalized 缺失），而不是诚实记"测量不可用"。修复：逐视口记账"浏览器无法启动: …"，下游按测量不可信处理（`browser_observation` 的截图路径原本就有同级处理，此次补齐测量路径）。测试：`test_launch_oserror_recorded_per_viewport_not_raised`。
2. **`browser_version` 记入界面提示文本**：Windows 上 `chrome.exe --version` 曾退出码 0 且 stdout 为"已在现有的浏览器会话中打开。"——被原样当作版本号记入测量记录（本轮真实复现）。修复：新增 `extract_browser_version`（仅版本号样式的输出才采信，否则 unknown），render_measurement 与 browser_observation 共用。测试：`BrowserVersionValidationTests`；真实复测确认该字段如实记 unknown（Chrome 文件版本 154.0.8037.58 继续按 E1 口径单独记录）。
