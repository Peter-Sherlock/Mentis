## 4. JSONL 字段核对（本机 CLI 帮助 + 已有材料，零外部调用）

- Codex CLI：`codex --version` → **codex-cli 0.158.0**（2026-09-29 实测）。
- Adapter 消费的 `codex exec --json` stdout 流事件类型（P3.1 解析器 + 保存的事件文件印证）：`thread.started{thread_id}`、`turn.started`、`item.started{item{type,status}}`、`item.completed{item{type,status,text}}`、`turn.completed{usage}`、`turn.failed`、`error{message}`。
- Codex 自留 rollout 会话文件（既有 09-28 文件，29 行，逐字段枚举）：顶层 `session_meta`（cli_version/cwd/git/model_provider…）、`event_msg`（item/token_count/task_complete/error + thread_id/turn_id/duration/started_at_ms…）、`response_item`（call_id/output/status，含加密推理）、`token_usage_record`（turn+total 用量）、`turn_context`（approval_policy/model/sandbox_policy）、`world_state`。item.type 实测出现：Reasoning×13、CommandExecution×11、AgentMessage×6、UserMessage×2、ImageView×2、FileChange×1。
- **含义**：stdout 流（我们唯一自动消费的通道）字段远少于 rollout；事件级时刻、命令输出、最终消息都在 rollout（私有层，仓库外）。该差距决定 T2 的流式映射上限与 T1 的"可见/不可见"展示边界，已写入[契约](../TRACKING_EVENT_CONTRACT.md) §8。
