## 2026-09-28 核查与更正

用户要求审视实际进度并直接修复问题。上文保留初次报告原状；其中 API ID、输出价格、Mock 标注、用量和下一包顺序须以本节及[当前状态](../DEVELOPMENT_STATUS.md)为准。

1. 官方 V4.1 Flash 的请求模型名是 `deepseek-flash`，不是初报的 `deepseek-v4.1-flash`；峰段输出为 $1.20/百万 token、谷段 $0.60/百万。已同步网关默认值、ADR-007、配置和状态。依据：[官方发布说明](https://api-docs.deepseek.com/news/news260910/)、[模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)。
2. 默认绑定方法每次访问都会产生新对象，原 `self._transport is not self._http_transport` 恒为真，**真实 HTTP 成功也会被记成 Mock**。已改为构造时记录是否注入传输；模拟 HTTP 的离线检查确认默认路径记 real、注入路径记 Mock。
3. 原 HTTP 传输只返回 content，服务端 usage 被丢弃。现提取并汇总 token 用量；追加日志中的本地调用 ID 也改为跨命令唯一。HTTP 错误与意外异常只记录错误类型或状态码，不记录可能含凭据的响应正文。测试用虚拟服务端返回，不代表真实计费已验证。
4. 原解析器允许 `{}` 被当作无错误结果，并允许 `request_user` 没有字段完整的请求。现拒绝缺失/类型不对的顶层字段及空决策请求；报告改称“结构与引用通过的候选”，明确**证据 ID 存在不等于解释正确**。决策请求三要素完整也不证明提问必要。
5. P1.2 契约演示的页面没有真实报名表单，且未做对比度测试；原“对比度抽检通过”及网页整体 accept 表述误导。现把脚本的目标与检查明确限定为文件写出/存在，保留不完善页面供 P2.2 诊断。Mock 候选同步调整为两种演示页都真实存在的自指向报名链接缺陷。
6. CLI 增加显式 `--real`；仅凭环境里有密钥不触发网络请求。单次命令的模型循环最多两次（含一次 JSON 修复）、每次输出上限 2000 token、输入文本上限 25000 字符；采用官方非思考模式，避免把无效的 temperature 当控制量。这些是每次执行的技术边界，不是全阶段费用上限。真实调用前仍须核对输入范围与实际价格。

## 2026-09-28 真实调用与语义对照

用户已在本机 `.env` 设置密钥，并明确要求测试 API、进入下一开发包。本轮只检查凭据存在，不显示值。测试数据限定为 `runtime/demo/event_page_v1.html` 合成活动页、合成目标与用户反馈；每次 CLI 命令最多两次请求，实际成功的两轮各一次。首次默认沙箱连接返回 `PermissionError`，无模型响应/用量；按已授权范围重试后得到真实响应。

第一次成功响应：`deepseek-flash`，服务端 usage 为输入 1,155 / 输出 956 tokens。模型报告页面缺少日期、地点、价格；对照原始 HTML 可见这三项都在普通 `<p>` 文本里。根因是观察器当时只输出标题与链接，漏掉正文。这是**观察缺陷诱发的语义错误**，不能算专业判断正确。

修复后观察记录新增 `dom_text` 条目，明确排除 `<head>`/脚本正文；普通段落中的时间、地点、价格现在作为 `text:1` 传入模型，并在边界声明“未观察到不等于实际页面缺失”。相关回归检查通过。第二次真实响应：输入 1,249 / 输出 1,000 tokens；不再报告三项信息缺失，指出静态 DOM 中的 `href=#signup` 自指链接没有实际 `form/input/button`。原始 HTML 与 P3.1 截图可独立核查该问题。记录位于 `runtime/diagnosis/diagnosis_20260928_051639.{json,md}`，调用日志在同目录 `call_log.jsonl`；均被 Git 忽略。

第二次响应仍不是“专业性通过”：一个“需要用户确认是否存在动态表单”的决策请求虽然字段完整，但当前源码与浏览器观察是可用的自主查证路径，不应转交用户。另一个关于信息层级的轻微判断依赖视觉呈现，静态结构不能支持，须等截图/交互评价。我们把它们记为**语义待复核/不采纳**，不因引用编号存在、JSON 合法或用户可能满意而接受。没有独立人类领域专家复核，也没有效果收益结论。

P2.2 的技术退出条件已满足：模型与结构观察输入都真实；无图像/交互时明确未知；格式和语义分账，失败及用量留痕。**P2.2 = completed（接入与诊断候选链）**，专业准确性仍是 P3.2/P2.4 的评估对象。下一包按依赖为 P3.1。
