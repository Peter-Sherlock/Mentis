## 2. 实现

### 2.1 新增 `mentis/evaluation_plan.py`（schema `mentis-eval-plan/1`）

- **四层来源组装**（`build_evaluation_plan`）：
  - **内核**（K1—K3）：约束/保留项/委托边界不被破坏（含不越界）、无回归、未验证不宣称已验证；来源 `core:*`。忠实于意图由 T1（素材事实核对）落实，不重复成条。
  - **用户**（U*）：brief 约束与偏好逐条入计划，沿用 `Provenance`/`source_ref`（如 `brief:v1:system-preset:isolation-no-network` + `provenance:system`）；可映射约束给确定性检查（无网络→外链扫描）。
  - **领域**（D*）：已加载 `resources/web_pilot` 规则；硬约束逐条（带 `id@版本` + `rule-nature:*`），guideline/preference 聚合为专业建议条目，hypothesis 聚合为待验证假设条目（明确"不阻塞交付，也不作为修改依据"）。已被任务实例条目落实的规则（IH-1/IH-2/BI-1）不单列，作为其 source_ref——保持计划短。
  - **任务实例**（T1/T2）：`derive_task_facts` 从标注化素材（`- 活动名称：…` 等）机械提取事实 needle 与报名表单要求；只提取已知标签、不虚构默认值；价格由 brief 后版本修正覆盖（"从 ¥99 改为 ¥129"取 ¥129）。
- **维度字段**：含义、类别（硬要求/专业建议/用户偏好/待验证假设）、来源层+来源引用、需要的观察、检查方式（deterministic / pairwise_blind / user_judgment / unverifiable）、通过线、是否阻塞、无法检查时的处置、优先级；计划级另写优先级与取舍、停止条件、不评估的范围。
- **阻塞规则**：`blocking = 硬要求 ∧ deterministic ∧ 非 provisional`。Mentis/模型推导条目 `agent_selected+provisional` 永不阻塞；hypothesis 永不阻塞。
- **标准写结果不写实现**：通过线如"价格「¥99」可见"，无字号/位置/像素规定。
- **确定性检查执行**（`execute_structural_check`，collab 结构观察阶段调用）：`text_contains`（事实 needle）/ `form_fields_present` / `no_external_refs`（外链扫描）；`render_overflow` 条目如实标注"由渲染测量在专业评审段核对"，结构层不判。
- **模型实例化**（`instantiate_domain_rules_with_model`，现有 Model Gateway `deepseek-flash`，ADR-007）：提示词只给已加载规则、brief 条目、素材摘录与可用观察能力清单；输出条目校验——`source_refs` 每项必须是已加载规则 id 或 goal/brief/素材原话摘录（≤40 字），**虚构来源拒收并留痕**（`model_instantiation.rejected`）；类别/检查方式不合法、含义或通过线缺失同样拒收；最多接受 4 条（保持计划短）；模型条目一律 provisional 不阻塞；模型自称 `deterministic` 的降级为 `unverifiable` 并留痕（防止虚构自动检查能力）；disposition 误填标签时回退默认处置文本。
- **版本化修订**（`revise_plan`）：仅 `brief_revision` / `goal_change` / `standard_error` / `new_blind_spot` 四种原因；出新版本文件并写 `revision = {reason_kind, detail, supersedes_version, affected_entries}`（受影响条目如"价格: ¥99→¥129"）；旧版本文件字节不改写。
- **视图**：`render_plan_markdown`（CLI/报告用）、`acceptance_block`（委托指令的"本轮验收项"段）。

### 2.2 collab 接入（`mentis/collab.py`）

- **先落盘后委托**：`_dispatch_codex` 首行 `_ensure_evaluation_plan()`——不存在则组装 v1，brief 版本/目标变化则改版；计划 JSON 落盘 `run_dir/evaluation-plan/plan-vN.json`，**落盘失败抛 `PlanPersistenceError`，该次委托不发起（执行器零调用）**，与 prompt 落盘失败同一纪律。
- **哈希入 trace**：落盘后计算 SHA-256，`evaluation_plan.recorded` / `evaluation_plan.revised` 事件（source=mentis）refs 携带 `{path, sha256, role: plan}`；两个新 kind 与 role=plan 按[追踪契约 §16 附录](../TRACKING_EVENT_CONTRACT.md)记录理由。生成时 `notify_progress`（不阻塞、不等待）。
- **委托事件引用计划**：每次 `delegation.prepared` 的 refs 同时含 `prompt` 与 `plan`；委托文本尾部追加"本轮验收项"段（计划阻塞条目 + 行为类要求提示），归档哈希=实际发送文本。
- **委托 prompt 事实派生**：`build_delegation_prompt` 的 [硬要求] 事实清单改为 `facts=self._expected_values()`（计划任务实例条目），消除"价格 ¥99"硬编码在 brief 改版后的指令漂移（此前修订指令会同时含硬编码 ¥99 与修正说明）。
- **硬要求检查读计划**：`hard_requirement_review` 遍历计划中结构阶段可执行条目并逐项产出 findings/blocking（条目 id 可追溯）；计划缺失视为异常状态（不冒充通过）。
- **保留项/预期值**：`_expected_values` / `_preserved_items` 读计划 needle；`deterministic_checks`（专业评审段复检）签名与逻辑不变，输入变为计划派生值。
- **结果绑定**：`professional-review.json` / `professional-verify.json` / `state.json` 记 `evaluation_plan: {version, sha256}`；`review.recorded` 事件摘要带"依据评估计划 vN"（追加式）；恢复（`collaboration_from_state`）从磁盘加载最新计划、重算哈希，不改写、不重复改版。
- **素材可注入**：`Collaboration(material_text=...)`，缺省仍为合成试点素材（COPY_DECK，虚构品牌）；工作区 `input/copy.md`、计划任务实例层、prompt 事实清单同源。
- **未改动**：权限规则、ADR-002 默认自主、预算、单写入者、`_adjudicate_candidates` 与 `run_model_review` 逻辑（V2）、`docs/evaluation/e1/` 冻结字节、两个 T4 历史运行目录。

### 2.3 CLI 与报告

- `py -3.14 -m mentis eval-plan --goal "..." [--material <文件>] [--pilot] [--real] [--out <路径>]`：默认离线组装并打印 Markdown 计划；`--pilot` 用内置合成素材演示四层完整计划；`--real` 调 DeepSeek 实例化（需凭据，发送目标/brief/素材摘录/已加载规则）；`--out` 同时写 JSON。
