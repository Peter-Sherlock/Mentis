## 重大更正：P2.3/P3.1 的"移动端截断"是截图采集假象

实测发现 Windows 无界面 Chrome 有 **500px 最小窗口宽度**（Chrome 154，2026-09-28 实测）：`--screenshot --window-size=390` 实际按 500px 布局渲染，再把 500px 画面裁成 390 宽 PNG。P3.1/P2.3 据此得出的"Run A v1 移动端右侧文字截断"**不成立**——真实 390px 布局下该页无横向溢出、无容器内裁剪、渲染完整。三组独立证据：

- 注入式渲染测量（真实 390 布局）：`runtime/guidance/measure-v1/`——mobile innerWidth 390、scrollWidth 390、溢出 0px、溢出元素 0；
- 对照截图：`runtime/guidance/artifact-test/wrapper-true390.png`（真实 390 iframe 渲染，"好奇心即可。"完整换行）vs 原始假象截图 `runtime/collab/20260928_070129-c1e4/observation/mobile.png`（500 布局被裁，文字在图像边缘截断）；
- Run C v2 重测（`runtime/guidance/measure-runc-v2/`）同样无溢出。

**处置**：`browser_observation.py` 移动视口改用 iframe 包装（PNG 仍为 390×844，布局真实 390），limitations 记录此更正；P2.3 的历史报告按约定不篡改，以本节为准。DeepSeek 图像探测中对假象截图的"截断确认"同样作废——**模型看了假证据会说假话，观察链的真实性是一切判断的前提**。

## 未验证与限制（如实）

- **改善是单案例的**：一个缺陷、一次修订、一个页面。"Mentis 指导能改善作品"不因此成立——跨案例收益属 P2.4 强基线比较。
- 视觉质量仅由"模型看截图 + 数值测量"判定；无人类专业复核；对比度、部署行为、真实点击手感未验证；表单为声明行为 + 同步 DOM 变化，真实网络请求未捕获。
- 决策分流是确定性关键词规则（变更动词+保留名词/新事实提示），存在误判风险，已声明；更完整的语义分流属后续。
- 执行器中断的真实恢复依赖其会话配额恢复（等待 ~50 分钟）；Adapter 本身仍无中途恢复能力。
- 模型复查结论未被独立复核（复查者与诊断者同为 deepseek-flash）；本轮无决策请求等待用户回答的真实 resume。
- 领域资源仍为草案（pending_human）；诊断中 4 条正面观察被拒收属校验器按"缺陷需候选"规则办事，不代表其观察为假。
