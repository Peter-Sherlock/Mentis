# Mentis 运行可观测性补强计划

版本：v1.2｜2026-10-08｜归属：P2.4 内部 O1—O3；22 个顶层工作包与包间依赖不变。实际进度以[状态文件](DEVELOPMENT_STATUS.md)为准。O3 页面段先行后，依次补 O2、[C1 专业配置](LOCAL_PRODUCT_ROADMAP.md)和 O3 完整核验；浏览器交互归 P3.4，自动优化后置。

负责人明确先在网页制作任务上跑通专业指导闭环，再考虑写作、音乐等领域。本计划服务于网页体验主线：给出目标 → 首稿 → 自查与修订 → 必要节点介入 → 查看作品、变化与依据。

## 1. 问题与当前证据

让负责人能检查：Mentis 是否理解目标、依据什么作出专业选择、给执行器发了什么、执行器实际报告了什么、作品如何变化、为什么接受或没有修改。

规划轮起始 Git：`c555497`，工作树干净。2026-10-08 只读核对得到：

| 已观察到的问题 | 当前证据 | 开发处理 |
| --- | --- | --- |
| 对话视图省略 Mentis 的诊断与决策 | `mentis/trace.py:render_conversation` 未展示 `observation.diagnosis`、`decision.routed` 和评估计划事件 | O1：串起计划、观察、候选、程序处置、委托与复检 |
| 公开回复采集在入口间不一致 | `collab` 有公开消息全文归档；`eval_runner._dispatch` 只保留 160 字摘要 | O1：统一公开消息采集；摘要与全文分开，缺全文明确标记 |
| 静默期间没有可理解的状态 | `follow_timeline` 等待新事件；缺阶段起止与生产者活动信号，存在 manifest 静默收尾兜底 | O2：解释阶段、等待、耗时和最后可靠状态，处理恢复后的旧 manifest |
| 调用、判断与产物证据分散 | 指令、CallRecord、诊断、计划、截图、产物版本分布于不同文件 | O1 建立关联；O3 提供同一运行的只读页面 |

实际复现入口（在项目根目录运行，不调用模型或执行器）：

```powershell
py -3.14 -X utf8 -B -m mentis trace --run runtime/evaluation/e2-runs/20261004_055316-937e-input-002-M
py -3.14 -X utf8 -B -m mentis conversation --run runtime/evaluation/e2-runs/20261004_055316-937e-input-002-M
```

实际输出：时间线核验通过，可读事件 **10**、引用异常 **0**；对话视图仅显示 `[10] review.recorded`。真实模型指出“费用信息缺失”，程序因映射得分 **0.082** 判 `plan_blind_spot`，另有 `skip_unverifiable`、`keep_as_is`、`user_option`。结果是 **零委托、no_change，质量待独立评分**。零委托是实际行为；不能为了展示交流而补造 Codex 消息。

这个案例用于核验“能否看见问题与决策”。映射缺口另列后续方法改进，本包不调整映射或改写 E2 判定。

## 2. 完成后的四个查看入口

| 入口 | 必须回答的内容 |
| --- | --- |
| 当前任务 | 目标与保留要求；当前阶段与执行主体；阶段耗时、最后事件；可核对的预算用量；是否需要用户决定及其影响范围 |
| 专业决策 | 问题、实际观察、对应目标/计划维度；模型建议、程序规则、用户决定分别标注；采用/保留/待决/无法验证及原因；后续动作和复检结果 |
| 公开交流 | 确切委托、执行器公开进度/最终回复、工具动作及其实际状态、Mentis 后续处置；默认简明，原文可查看 |
| 作品与变化 | 当前可打开的作品；同视口前后截图与文件差异；brief/计划/产物版本和哈希；触发修改的记录及复检依据 |

这些是 O1—O3 的总目标，O1 先交付记录与回放。**执行器结束、作品可交付、质量改善分别展示**。推理条目仍只显示类型，不读取内部推理，也不生成事后解释填补原始证据。

## 3. 共用记录与投影规则

1. 复用 [追踪契约](TRACKING_EVENT_CONTRACT.md) 与现有 `trace/events.jsonl`、manifest、计划及诊断材料；CLI 和页面共用读取/投影逻辑，不能各自重算业务判定。投影可再生成，不成为第二事实来源。
2. 可见记录尽量关联 `run_id`、事件 `seq`、阶段、`attempt_id`、brief/计划版本、候选 ID、产物版本/哈希、证据路径/哈希。来源区分“原始记录”“按现存文件确定性读取”“未采集”；未采集显示 `unrecorded`，无法核验显示 `unverified`。这两个展示标签不成为新业务判定。
3. 新运行保存模型候选与程序处置的对应关系、真实映射方式/得分及引用。历史运行只按现有材料展示；缺明确关联时标缺口，不猜测候选、阶段、时间或版本。
4. 委托全文继续“先归档再发送、哈希绑定实际文本”。公开消息全文与有界摘要分别保存；采集失败需降级完整性并显式显示，不能在回调中吞掉后继续声称完整。
5. 模型调用复用 CallRecord：请求 ID、模型、时刻、耗时、实际 usage、输入哈希/图像指纹、响应/错误引用、Mock 与 HTTP 是否实际发起。把已采集的调用关联到计划、诊断或复检；模型输入全文未保存时明确标记。模型调用次数、HTTP 请求数、执行器委托数分别记账；没有用量或价格依据时显示未知，不填 0 或虚构货币成本。
6. `mentis-trace/1` 老事件保持可读。新增可选字段、kind 或 refs role 必须补契约附录与兼容测试；投影可另定义版本化格式。规划轮不预先宣称新契约已实现。
7. 原始 prompt/事件/manifest、E1 冻结源、E2 协议/运行材料/评分材料不可回填或覆盖。新回放产物写独立输出目录；新代码产生的冒烟记录按新版本单列，不并入原 E2 数据。
8. 沿用既有隐私边界：本地确切委托可查看，分享导出须脱敏；不解析私有 rollout、密钥或整份作者答案/评分材料，不向受测流程回灌视图内容。

## 4. 实施顺序与退出门槛

### O1：统一记录与可读回放

- **前置：** 现有 T1—T3、V1/V2 记录链；不依赖 E2 人工评分完成。
- **工作：** 统一 `collab`、`guide-revise`、`eval-run` 的公开消息采集；补齐 conversation 中的计划、诊断与决策；提供共用运行投影和 Markdown/CLI 回放，关联现存模型调用及产物证据。
- **交付：** 可执行回放入口、决策视图、公开消息全文引用、版本与证据索引；明确不支持或未记录的字段。
- **退出：** 真实 E2 样例能连续看见“费用缺失 → 模型候选 → 程序拒收及 0.082 → 零委托 → no_change”；三入口的新运行采集通过同类离线回归；长公开回复尾部不丢失；旧记录缺口、坏哈希、越界引用正确降级；读取前后源材料字节不变；既有业务行为回归不变。
- **资源与预算：** 现有 Python、stdlib、运行文件和测试；真实模型/执行器调用 **0**。完整指令见 [P2.4-O1 prompt](prompts/P2.4-O1.md)。
- **停止点：** 记录与回放验收后交接 O2；本步不开发实时心跳或页面，不修专业映射。

### O2：运行阶段、等待与活动状态

- **前置：** O1 的共用记录与读取逻辑；现有 O3 只读页作为可见状态入口。
- **工作：** 在流程边界记录计划/执行/观察/评审/修订/复检的起止、关联调用和等待原因；提供生产者活动信号、耗时、最后事件、可核对的预算余量、用户决定是否阻塞。活动信号记录生产者、运行代次、时间、有效期和来源；恢复后旧信号/旧收尾不能覆盖当前代次。旁观器按可配置间隔刷新状态；刷新本身不代表生产者仍活跃。CLI、投影与现有页面共用最后可靠状态，不把活动信号等同于阶段进展。
- **退出：** 受控长等待、超时、异常、待决、终态和恢复场景均能说明最后可靠状态；旧 manifest 不使恢复中的旁观器误报完成；旁观器断开或 Ctrl+C 不停止任务。事件静默只表示暂无新记录，进程存活与阶段进度分别取证；无生产者证据时显示状态不确定，不假造百分比、不自行重试或解锁。
- **资源与预算：** 本地受控子进程、时钟/事件夹具与离线测试，真实模型/执行器调用 **0**；受控演练明确标为开发验证。
- **交付：** 共用状态投影、CLI/现有本地页的状态与等待展示、受控故障记录、前后页面对照；具体指令见 [O2 prompt](prompts/P2.4-O2.md)。
- **停止点：** 技术验收后交接 C1；专业配置绑定后再做 O3，真实模型环境验证统一在 O3 单列。O2 不提供反馈提交或执行控制。

### O3：本地只读运行页面与一次真实任务核验

- **前置：** 历史回放/记录跟随页面需 O1，可按用户新反馈先行；阶段/活动状态需 O1、O2，完整真实任务核验另需 C1 配置绑定。只读页面先行不授予 O2/O3 完成。
- **工作：** 共用投影提供轻量本地页面，包含任务状态、公开交流、决策、作品/前后版本；同一入口支持实时旁观与历史回放。无前版、视口不一致或引用失效时明确缺口，不拼接成有效前后对照。
- **退出：** CLI 与页面的事件顺序、处置、终态、缺口一致；实际可打开作品与两视口证据；受控故障验证页面可读且不误报。再做至多 **1 次独立真实网页任务冒烟**，记录输入、代码版本、专业配置版本/哈希、阶段引用、浏览器、调用预算、用量和真实输出；失败留档，不自动重跑 E2。真实资源未就绪则明确记未验收。
- **资源与预算：** stdlib 本地服务或静态页面、已有 Chrome/Edge 与产物；真实任务开始前登记现有机制能执行的委托/修订/模型请求/时间上限，JSON 修复产生的额外 HTTP 请求另计。页面只绑定本机、只提供选定运行的允许材料、转义外部文本，产物预览与查看器隔离。
- **停止点：** 更新状态并回到 P2.4 退出判定。聊天、反馈提交、暂停/续办等操作界面仍归 P3.4；只读页面不提供执行控制。

## 5. 资源与主要风险

| 项目 | 当前需要 |
| --- | --- |
| 开发 | 1 名熟悉 Python 和委托/评审链的开发者，按 O1→页面段→O2→C1→O3 核验单写入者推进；无需新增 Agent、数据库、队列或框架 |
| 验证材料 | 现有 E2 真实运行与长消息/故障夹具；历史资料缺失不触发付费重跑 |
| 真实环境 | O3 的本机浏览器、可用模型/执行器与一次登记预算的任务；O1/O2 可独立完成 |
| 人工证据 | E2 独立盲评、过程/守卫标签仍 `pending_human`；负责人体验单独取证，技术验收不由 AI 代答体验反馈 |
| 外部平台 | 外部追踪服务不是本包依赖；现有本地证据足够完成第一轮，不上传历史数据 |

优先风险：历史信息无法补齐、入口事件格式不同、恢复时旧收尾与新活动冲突、未绑定版本的结论被误读、采集异常被吞掉。按阶段回归；记录完整性与方法判定分开，视图不能改变 unknown/unverified、验收、预算或授权语义。
