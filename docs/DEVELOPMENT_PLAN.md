# Mentis 递进式开发计划

版本：v0.3.5｜2026-10-08｜当前进度见 [DEVELOPMENT_STATUS.md](DEVELOPMENT_STATUS.md)。下一版本按[本地产品路线](LOCAL_PRODUCT_ROADMAP.md)推进：运行状态 → 最小任务专业配置 → 真实任务核验 → 可靠的本地浏览器交互；自动优化后置。保留 22 个顶层包与包间依赖，C1 为 P2.4 内部步骤。

## 1. 本版的执行约定

本版按“尽早验证专业指导 → 检查价值 → 加固工程 → 多执行器 → 正式验收”推进。旧包编号保留原职责，新增 P0.3、P0.4、P5.2a，共 22 个包；**包编号不再表示开发先后，按下面路线和前置依赖执行**。

默认一轮一个包；用户已授权多个包时连续完成，逐包验证，不重复申请同一授权。用户指出缺失交付时按其最新目标落实修正；真实调用范围与预算单列，不由只读查看器推定。

先在网页制作任务上跑通，再考虑其他领域。[O1 指令](prompts/P2.4-O1.md)保留为记录与回放的实施依据；O3 页面段先行后，依次补 O2、C1 专业配置冻结和 O3 完整核验。下一轮实施指令见 [O2 prompt](prompts/P2.4-O2.md)。当前进度仅看状态文件。

产品默认按已授权目标自主推进，用户只在关键取舍、必要事实或授权边界介入；可主动选择共同设计。开发过程的“一轮一个工作包”是交接节奏，不是产品要求用户逐步批准。状态通知不等待回复，决策请求只暂停依赖该决定的动作；完整规则见 PROJECT_PLAN §7、§10。

历史决定与案例保存原交付状态，但不得以历史“完成”自动推定新范围已经通过。负责人已明确先跑通网页制作；其他领域仍为建议，可继续准备可逆的案例与实验设计，不伪造用户确认。

## 2. 接手及文档职责

先读根目录 AGENTS.md、状态文件、本计划当前包，再读 PROJECT_PLAN 的相关章节及 DOMAIN_STRATEGY。检查实际产物与 Git；不要读取 archive 作为现行实施规则。

总体规划负责产品和架构；本计划负责包依赖和验收；状态文件负责当前位置；ADR 负责决定来源；案例作者材料不得整份进入受测系统。

### 3.1 下一版本的体验目标与交付顺序

下一版目标：本机单用户启动服务后，通过浏览器给出网页目标，查看自主制作与检查过程，必要时回答决定或表达反馈，直接查看作品、变化和依据。当前只读页面是已有基础；完整交互须通过 P1.3/P1.4/P3.3 的相应恢复与故障门槛，再进入 P3.4。

| 顺序 | 开发范围 | 用户可体验的变化 | 关键门槛 |
| --- | --- | --- | --- |
| A1 | P2.4-O2 | 看懂当前阶段、等待原因和状态依据是否仍有效 | 活动与进展分列；静默、异常与恢复不误报；[O2 指令](prompts/P2.4-O2.md) |
| A2 | P2.4-C1 | 查看任务的专业职责、资源、边界和配置版本 | 配置先落盘再使用；阶段引用同一有效版本；盲评不接收原诊断答案 |
| A3 | P2.4-O3 完整核验 | 旁观一次含真实委托的新任务，核对作品与依据 | 登记预算；运行/配置/产物绑定；历史 E2 不回填、不重跑 |
| B | P1.3 → P1.4 → P3.3 → P3.4 | 浏览器发起、反馈、纠正和查看结果；刷新不重复委托 | 持久化、单写入、unknown 核对与中断状态有证据 |
| C | P2.4 方法验证及后续已授权评测 | 不同网页任务选择对应资源与检查办法 | 强提示词基线、独立评价及成本；任务族与配置分别绑定 |
| D | 后续受控优化研究，当前不安排实施包 | 新配置有比较记录、版本和回退依据 | 可复核指标、开发/未见案例隔离、独立评价及回归门槛先就绪 |

C 的材料准备与独立评审可在不依赖 B 的部分独立推进，不能据此启动未登记预算的运行。先验证网页内部任务适配，再研究其他领域；身份一致性与专业效果分别验收。资源与停止点详见[本地产品路线](LOCAL_PRODUCT_ROADMAP.md)。

## 4. 工作包详细说明

### P0.1：历史产品决定

- **前置：** 无。
- **目标：** 已交付历史决定材料；不重新伪造确认记录。
- **工作：** 核对原决定来源与当前变更记录；按新的 ADR 修订受影响项。
- **交付：** 原 ADR-001—005 及修订说明。
- **退出条件：** 仅证明对应决定记录已形成，不证明新领域获确认。
- **边界：** 不重做历史包。

### P0.2：历史 12 案例草案

- **前置：** P0.1。
- **目标：** 保留文档问答的回归材料及草案状态。
- **工作：** 修正可见性说明，保留原例内容与未复核事实；新产品案例进入 P0.4。
- **交付：** docs/cases/initial_cases.md。
- **退出条件：** 文档交付完成与专业复核状态分开；不得按旧声明认定当前全部前置已满足。
- **边界：** 不虚构复核，不将工程案例当作设计指导效果证据。

### P0.3：产品主线、领域策略与路线修订

- **前置：** P0.1、P0.2。
- **目标：** 按授权修订规划：在前移真实闭环的基础上，把默认自主委托与关键介入落实到执行及评价。
- **工作：** 更新总体规划、开发顺序、领域策略、ADR 和状态；修复案例可见性；保存历史快照；核对链接、依赖与决定状态。
- **交付：** 规划 v0.3、DOMAIN_STRATEGY.md、相关 ADR 与 docs/progress/P0.3.md；ADR-006 保持 proposed。
- **退出条件：** 当前与历史清楚；包顺序无循环；新领域标为建议；无业务代码或虚构调用。
- **边界：** 不初始化 Git，不进入业务实现，不把文档修订等同 P0.4 已完成。

### P0.4：专业指导案例与评价视图

- **前置：** P0.3。
- **目标：** 让首个真实闭环知道要验证什么。
- **工作：** 按暂定网页试点设计九类案例：原六类反馈链，以及自主完成、必要介入、用户撤回/改变方向；每例拆分用户、运行输入、作者标注、评测视图；明确首稿及修改后实际产物的采集办法。
- **交付：** 新的试点案例草案、评分量表、基线与用户反馈协议；旧 12 例单独保留。
- **退出条件：** 每项评价有情境依据；不虚构隐藏偏好；运行输入白名单排除预期答案，实际隔离由 P2.4 验证；自主推进与必要介入两侧均有案例；草案/负责人复核/独立复核三种状态分开。未人工复核可做探索，但不能用于专业结论。
- **边界：** 不批量生成 80 例；不把书面首稿当真实作品。领域暂定状态保留，不伪造用户选择。

### P1.1：Git 与最小工程

- **前置：** P0.4。
- **目标：** 建立可追踪的实施起点。
- **工作：** 在用户指令进入工程范围后检查现有目录；初始化本地 Git 并建立文档基线；设置忽略凭据/运行资料；建立 Python 最小入口及必要检查；明确新案例仍可能待复核。
- **交付：** Git 基线、运行入口、安装说明、必要检查记录。
- **退出条件：** 入口真实可运行；提交标识真实；无凭据进入追踪；未创建全部未来模块。
- **边界：** 不创建远程仓库，不发布，不接真实模型。

### P1.2：轻量任务与反馈契约

- **前置：** P1.1。
- **目标：** 为一轮协作保存必要上下文，不先建立完整专业规格平台。
- **工作：** 保存 brief、来源与偏好、动作目的、原生尝试身份、产物/评审版本与前后关系；增加最小 DelegationPolicy（代决范围、保留决定、执行范围/预算、介入触发、来源与版本）和 InteractionRecord（notify_progress / request_decision、阻塞依赖、回答来源）。区分 user_selected、agent_selected、provisional；规则从现有指令推导，不要求用户填表。
- **交付：** 最小数据对象、可读导出、序列化与关键不变量检查。
- **退出条件：** 可回查同一目标的首稿/反馈/修订；执行完成、系统检查通过与用户满意分离；通知不转为等待；缺少必要授权不能执行，旧授权和用户沉默不能批准新范围。
- **边界：** 不实现通用本体、全量对象表或完整恢复系统；未确认执行状态不得自动重发。

### P2.1：首领域资源与行动依据

- **前置：** P1.2。
- **目标：** 专业知识影响动作、诊断和修改。
- **工作：** 实现小型资源元数据与按需加载；首试点包含信息组织、视觉表达、基础交互的必要依据及反例；把缺口按信息归属、重要性、可逆性与获取成本分流到自主选择、工具查询、执行器咨询、小样实验或用户决定；验证未知领域、资源冲突、缺观察能力的受限处理。
- **交付：** 首领域资源、选择记录、反馈模式及少量回归例。
- **退出条件：** 规则区分硬要求/建议/偏好；同一流程可加载不同资源；无能力时明确未知；能说明为何自决、查证、小样或请求用户；常规专业问题不得仅因不确定就转交用户，不因追求零提问而省略必要介入。
- **边界：** 不为每个领域生成完整 Agent，不自动执行外部 Skill 代码，不以加载资料证明专家能力。

### P2.2：真实模型的判断、观察与诊断

- **前置：** P2.1。
- **目标：** 验证真实模型能处理本试点输入与产物证据。
- **工作：** 明确认证、数据与预算后接一个模型；记录版本和调用；针对实际可用的图像/结构/交互记录生成诊断、下一动作与修改候选；每个决策请求必须给出阻塞原因、用户独有信息或授权依据、已排除的自主路径；核对来源与结构，处理观察缺失和虚构位置。
- **交付：** 真实调用、候选处理、失败记录、可观察范围说明。
- **退出条件：** 模型与观察输入真实；缺图像或相关交互不得声称对应检查通过；格式合法与语义正确分开。
- **边界：** 不同时接多家主模型、不微调；此包不声称执行闭环或用户收益成立。

观察输入可以先来自已授权的固定样例；没有可用画面或交互记录时，对应诊断验证保持未完成/未知，不伪造数据。P3.1 补齐真实产物观察链，P3.2 进入视觉指导前必须验证该链可用。

### P3.1：第一执行器与产物观察接口

- **前置：** P2.2。
- **目标：** 尽早确认真实委托和实际产物能进出系统。
- **工作：** 核对 Codex 当前官方接口、运行时、认证与范围；隔离任务中先读后做一个小改动；收集真实任务身份、文件、日志与预览；核对继续会话和事件；验证本地网页可渲染、检查和捕获；保留拒绝及超时未知路径。
- **交付：** 最小 Adapter、能力矩阵、实际产物观察记录。
- **退出条件：** 任务与产物可定位；基本权限、预算、版本和单写入已落实；无原生能力时如实标记 emulated/unsupported/unknown。
- **边界：** 不等完整持久化才接执行器；不把缺失恢复能力伪装为支持，不自动部署。

### P2.3：默认委托、可选共同设计的 CLI 协作

- **前置：** P3.1。
- **目标：** 用户给出目标后能把常规专业判断委托出去，并查看实际作品。
- **工作：** 连接目标、委托策略、资源、模型与执行器；默认自主制作、检查和修订，通过非阻塞通知展示进展。用户主动共同设计时支持方向样例与选择；支持不知道、不满意、保留某部分、撤回与改变目标。CLI 用产物链接/本地预览展示网页。
- **交付：** 自主与共同设计两条可运行路径、版本化 brief、策略与交互记录。
- **退出条件：** 存在用户不再回复仍能完成的有界任务；notify 不阻塞，request 只阻塞相关动作；执行器反问先由 Mentis 解决；必要介入未回应时不越界，独立工作可继续；明确修正传播到下一委托，已有适用授权无需重复确认。
- **边界：** 不强制先写完整规格、不把共同设计变成默认问卷、不用执行摘要替代作品。

### P3.2：最小真实指导与修订闭环

- **前置：** P2.3。
- **目标：** 检验 Mentis 是否真的能提出可执行的改进指导。
- **工作：** 在已授权的模糊目标下自主获得真实首稿；观察后记录诊断、依据、保留项和具体修改；由同一执行器修改并比较前后；覆盖真实问题及受控错误、合格不改和修改回归；增加一条无需中途用户回复的任务和一条必要介入路径。初始自动修改最多两轮，预算来源明确；不要求用户给每次修订打分才继续。
- **交付：** 真实首稿、反馈、修订稿、检查与成本轨迹。
- **退出条件：** 至少一条真实指导链和明确的改善/无改善记录，以及自主/必要介入路径证据；已满足条件与保留项复检；失败如实报告，不把跑通当效果成立。发现无收益仍可完成实验交付，进入 P2.4 分析，不能标专业能力通过。
- **边界：** 不要求第二执行器；不凭一次改好宣称有效；不以改写评分标准收敛。

### P5.2a：早期真实使用与交互反馈

- **前置：** P3.2。
- **目标：** 在工程加固前检查用户能否有效委托、低负担查看结果并保有控制。
- **工作：** 先由项目负责人真实使用，也可纳入少量目标用户；分别记录默认委托与自愿共同设计的行为、阻塞次数、耗时、控制感、否定和纠正；区分研究者提示与系统贡献；整理阻碍有效沟通的问题。
- **交付：** 经允许保留的真实使用记录和问题优先级。
- **退出条件：** 有人实际操作；自用和独立目标用户证据明确区分；无人时标未完成，不能用模拟器冒充。
- **边界：** 不推断普遍收益、不自动联系外部人员、不要求已完成完整 UI。

### P2.4：指导价值与强基线比较

- **前置：** P3.2。
- **目标：** 在扩大工程之前检验反馈与下游结果，而非只检查规格。
- **实施顺序（v0.3.5）：** 以下均为 P2.4 内部递进，不增加顶层工作包总数。O3 页面段先行后，依次补 O2、C1 和 O3 完整核验；交互式聊天与执行控制归 P3.4。P5.2a 真人记录若尚不可核对，技术段可以继续，真人感受结论留空。

### P1.3：持久化与状态恢复

- **前置：** P2.4。
- **目标：** 把已观察到有效或需继续验证的循环保存可靠。
- **工作：** 依据当前价值结论限定范围；完善 SQLite 的状态、关键事件、事务和迁移；重启恢复专业配置、策略版本、真实待决定事项及产物版本，通知不恢复为等待；记录未知执行状态，不自动重复提交；任务生命周期独立于浏览器连接。
- **交付：** 持久化、恢复说明与必要测试。
- **退出条件：** 本地状态恢复真实；重复事件不重复推进；撤回后旧授权不复活、旧回复不批准新范围；摘要不成为第二事实来源。
- **边界：** 不做分布式事件溯源、长期用户画像或恰好一次执行承诺。

### P1.4：离线工作流与故障回归

- **前置：** P1.3。
- **目标：** 为真实闭环补齐可重复的失败检查。
- **工作：** 用明确 Fake Executor 回归旧版本、重复事件、授权拒绝、循环预算、资源缺失、目标改变、通知不阻塞及沉默不视为许可；沿用真实闭环的接口和状态，不另建平行实现。
- **交付：** 离线回归与状态不变量证据。
- **退出条件：** 假执行结果必须经审核；拒绝不绕过；合格停止与能力不足路径可检查。
- **边界：** 不把 Mock 当真实调用；本包后置不意味着真实执行前可省略基本权限与版本检查。

### P3.3：真实恢复、拒绝与中断

- **前置：** P1.4。
- **目标：** 验证外部副作用与本地记录的一致处理。
- **工作：** 注入提交超时、进程退出、执行失败、用户撤回与改变目标；核对原生任务与工作区再续接；处理中断请求和已确认停止的区别；检查单写入、拒绝和晚到结果。
- **交付：** 真实故障记录、恢复指引与必要回归。
- **退出条件：** 不盲目重发；拒绝不靠换执行器绕过；无法确定则保持 unknown；中断后的文件可核对；拒绝/撤回后不发新写入，晚到结果不自动验收或恢复旧目标。
- **边界：** 不宣称中断等于回滚或任何情况都能自动恢复。

### P3.4：本地浏览器任务闭环与产物对比界面

- **前置：** P3.3。
- **目标：** 本机单用户从启动到网页交付都能通过浏览器操作，先作为可体验的本地版本。
- **工作：** 提供自然语言任务发起、工作区/范围与预算摘要、进度、决定答复、反馈与目标纠正、作品预览、前后比较和按需证据；复用 O1—O3 投影、C1 配置及既有协作接口。页面展示请求暂停与实际停止的区别；前端不复制权限、验收或恢复规则。提供启动、运行条件和模型/执行器接入说明，区分本地服务与联网推理。
- **交付：** 本地服务入口、浏览器工作台、启动/恢复说明、完整操作与用户可用性记录。
- **退出条件：** 浏览器内完成一次真实目标→委托→观察/自主修订或合格不改→交付→反馈的有界任务；用户无需逐项专业审批。刷新/重连不重复提交，关闭页面不丢任务记录；待决只阻塞依赖动作；异常后可看已保存作品和最后可靠状态。看结果/看变化/看依据都可操作；专业配置与调用、产物版本可核对。
- **边界：** 本机单用户，不需要域名或公共部署；不做产品账户、计费、多租户或复杂管理后台。写操作接入前满足本包前置及现有授权、单写入、unknown 规则。

### P4.1：第二真实执行器

- **前置：** P3.4。
- **目标：** 验证共用委托与观察接口。
- **工作：** 核对第二运行时官方接口和本机能力；执行与首运行时等价的探测；实现 Adapter；保留能力差异和降级说明；运行隔离任务。
- **交付：** 第二 Adapter、真实产物与能力矩阵。
- **退出条件：** 真实调用不同执行运行时；不靠换模型冒充；核心无不必要厂商条件分支。
- **边界：** 不接第三执行器，不声明任意 Agent 已兼容。

### P4.2：跨执行器闭环与任务连续性

- **前置：** P4.1。
- **目标：** 切换执行资源时目标、评审、委托边界和用户偏好仍一致。
- **工作：** 在等价基线执行同组任务，使用相同评价；检查续接、反问和权限差异；确认旧执行停止后再切换；通过 Mentis 保存的上下文传递，记录丢失能力。
- **交付：** 两运行时修订链和兼容报告。
- **退出条件：** 目标、标准、策略版本及撤回状态一致，切换不扩权；不能以重发任务冒充原生会话迁移；不并发写同一工作区。
- **边界：** 跨执行器通过不等于跨领域通过；新增领域试验不是本包隐含范围。

### P5.1：冻结后的保留集评测

- **前置：** P4.2。
- **目标：** 形成有边界的正式效果结论。
- **工作：** 按开发成本和评分稳定性选规模；完成人工独立复核与按族隔离；运行前冻结版本/阈值/预算；进行预定对照、必要消融（至少包括 ADR-008 的"无评估计划"与"非盲复检"）和盲评，报告失败、分歧及不确定性。
- **交付：** 正式报告、原始记录索引、配置与限制。
- **退出条件：** 运行输入不含答案；无复核则不作正式结论；有收益/无收益/不确定都如实；不得临时降低门槛。
- **边界：** 固定 80 例不是充分性保证；保留集调参后要更换未见集。

### P5.2：独立目标用户试用

- **前置：** P5.1。
- **目标：** 复核完整产品对真实目标用户的作用。

- **交付：** 经允许的试用资料、评价和局限。
- **退出条件：** 真人、独立目标用户、自用三种证据明确；无参与者不能宣称完成；小样本不证明普遍有效。
- **边界：** 不自动联系外部人员或公开资料；不以模型模拟替代。

### P5.3：MVP 交付与能力声明

- **前置：** P5.2。
- **目标：** 让实际能力、文档和证据一致。
- **工作：** 核对完整 MVP 两执行器、有效指导路径、基础恢复、评测和试用；整理安装、限制、成本和恢复说明；未通过项保留；提出后续领域迁移研究但不自动执行。
- **交付：** 可复核版本、验收与限制报告。
- **退出条件：** 明确 MVP 通过或工程可运行但价值未证实；每条能力有证据；不得把未知领域加载能力称为专家能力。
- **边界：** 不自动推送、发布、部署或扩展新领域。

## 6. 验证与状态

| 证据 | 可以声称 | 不能声称 |
| --- | --- | --- |
| 文档/书面案例 | 方案可审阅 | 能力已实现或人工已复核 |
| 离线契约/Mock | 对应流程正常 | 真实模型或集成正常 |
| 真实调用/产物 | 声明范围内已运行 | 专业判断正确或带来收益 |
| 修改前后对比 | 该案例的变化 | 变化由 Mentis 独立造成 |
| 公平对照与独立评价 | 有边界的效果结论 | 全领域或全任务有效 |

状态使用 not_started、in_progress、partial、blocked、completed、superseded。包交付完成可以包含负面实验结果，必须另写功能/价值是否通过；不得把“实验做完”写成“效果成立”。

文档改动检查引用、依赖与状态一致性；代码只运行相称的关键测试；实际集成要有真实身份与产物；反馈能力要有前后版本和独立评价。不要为低影响文案写实现镜像测试。

## 7. 每轮报告与交接

记录工作包、授权范围、起始事实、变更、产物、实际验证、未验证、退出条件、剩余事项、Git 状态与下一包。代码包写 docs/progress/<包编号>.md；文档包可链接真实材料。保留原有失败记录。

每轮另须提供可亲自观察的交付（AGENTS.md 第 6 节）：实际入口或产物路径、用户可亲自完成的一次操作及预期结果、实际观察到的结果、Mock 或未实现部分清单；涉及产物修改附同条件前后版本。纯文档轮次明确说明无新增可运行功能。可观察交付供用户随时查看，不要求用户实际操作或回复才算每包完成。进度展示以用户可体验的变化为主线（给出目标 → 自主产出首稿 → 自行检查修订 → 必要节点介入 → 查看结果与依据；共同设计按需开启），与按技术依赖验收的工作包分开记录，不互相替代。

“继续”从状态入口的下一包开始，先检查其实际前置；修复请求按问题范围处理，不重新走所有包。选择已明确时不重新提问。
